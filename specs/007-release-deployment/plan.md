## C042 — 기본 Compose와 제출용 앱 연결 (구현 전 계획)

현재 서버 정적 JS는8자리를4칸에 표시하고 저장소는6칸에1자리씩 표시한다. 이미지 재빌드가 누락된 배포 문제이며 SYNC-002의6자리 구현을 다시 만들지 않는다.

- `configure-runtime.mjs`는 Node24 내장 기능으로 `.env.runtime` 주소를 읽고 기본 Compose proxy의 공개 CA만 복사한다. CA로 health를 검증한 뒤 기존 contest의 `chagok_server_config` 입력으로 전달한다. run-as·개인키·목업 토큰을 사용하지 않는다.
- 현재 서버를 새 소스로 재빌드/재생성한다. DB·미디어 볼륨은 유지한다. 제공 중인 JS/CSS와 저장소 해시 일치, 실제 제공 자산에서6칸·선행0 표시를 독립 브라우저로 검증한다. 가족 API는 합성 응답으로 대체한다.
- README는 기본 서버+제출용 앱과 기존 probe 디버그 흐름을 구분한다. 팀원용 configure-release 경로는 그대로 둔다.
- 실행 검증은 실제 맥북 기본 서버와 현재 contest 앱의 설정 확인창까지다. 가족 연결/자동 동기화 완료는 사용자의 코드 입력 및 별도 검증 없이는 주장하지 않는다. 기존 실행 중인 에뮬레이터를 중지하거나 앱 데이터를 지우지 않는다.

정합성 검토: DEP-004/007과 SYNC-002의 실행 경로 보완이다. APK 내부 동작·6자리 계약·원본 보존·명시적 서버 적용 경계를 변경하지 않는다.

## C049 — Windows 업데이트 시 DB 비밀번호 불일치 방지 (구현 전 계획)

사용자는 새 ZIP을 새 폴더에 풀고 README의 최초 `init`을 반복했다. 이전 `.env.team`은 삭제했지만 고정 팀 프로젝트의 PostgreSQL 볼륨은 유지되어 `diary_migrate` 인증 오류28P01이 발생했다. 사용자 제공 Windows 출력에서 DB healthy/migrate Exited1/web·proxy Created를 확인했다. 사용자는 이전 데이터 초기화를 명시적으로 선택했다.

- `init`이 Docker의 정확한 팀 데이터 볼륨 이름을 조회하고 기존 DB/음성/사진/목업 볼륨이 있으면 비밀 생성 전에 중단한다. 공개 CA만 남은 상태는 허용하며 다른 Compose 프로젝트는 건드리지 않는다. Docker 조회 실패도 초기화를 진행하지 않는다.
- `up` 실패는 웹 정상 기동으로 취급하지 않고 상태·migrate 로그 확인 및 기존 설정 복원 안내를 출력한다. `status`는 서버 성공을 전제로 하지 않고 Created/Exited 서비스도 조회한다.
- README 첫 설치 앞에 업데이트 절차를 배치한다. 현재 `.env.team` 보존/원래 설정 없는 경우/초기화 선택을 구분한다. 사용자 선택 초기화는 팀 데이터4개만 삭제하고 CA2개를 보존하는 명령이며 도구가 자동 실행하지 않는다. 실제 Windows 복구는 사용자 출력이 올 때까지 미확인이다.
- 격리 임시 폴더·대역 Docker CLI로 최초 생성, 기존 볼륨/설정 중단, Docker 장애, CA만 유지, 상태/실패 안내를 검사한다. 사용자 맥북 DB/에뮬레이터를 초기화하거나 재빌드할 필요는 없다. APK는 검증한0.2.10을 그대로 재포장한다.

정합성 검토: DEP-001/002/005/008의 실행·배포 안내 수정이다. 가족 데이터 보존 기본값은 유지하며 사용자의 Windows 초기화 선택을 다른 환경의 삭제 권한으로 확대하지 않는다. SYNC-008의 인증 무효 시 공유 사본 정리 경계를 안내에 반영한다.
