# 사진 첨부·재방문 회상 검증 — 2026-11-08

사용자 승인으로 수동 사진 첨부와 ‘다시 온 곳, 그때의 목소리’를 추가했다. 헌장1.3.0, FR-018/019, 데이터/HTTP/저장 계약, 계획, T044~T046을 갱신했다. 전체 서버/차량 통합 작업은 완료 체크하지 않았다.

## 실제 작동 범위

사진: 브라우저 IndexedDB의 일기별 Blob 보관, 여러 장 추가, 확대 열람, 개별 삭제, 새로고침 후 유지. 일기당8장·파일당10MB, JPEG/PNG/WebP 시그니처 및 이미지 디코딩 확인, 최대5천만 화소·긴 변2048px JPEG 사본 저장. SVG/HEIC·손상 이미지·초과 요청 안내. 서버 전송 없음. 원본 EXIF를 그대로 저장하지 않고 canvas에서 픽셀을 재인코딩한다. 원본 파일은 변경하지 않는다.

재방문: 샘플 녹음 좌표에서 300m 이내의 동일 샘플 가족 과거 기록을 최대3개 보여준다. 현재/미래/동시각/삭제/다른 보관함/위치 미확인/좌표 부재·오류는 제외한다. 같은 장소명만으로 연결하지 않는다. 예전 아반떼로 해변에 왔던 샘플 기록을 누르면 그 일기와 전체 녹음이 열리며, 사용자가 재생을 시작한다.

## 실행 결과

- `pnpm typecheck`, `pnpm format:check`, `git diff --check`: 통과.
- `pnpm test`: **58/58 통과** (기존49 + 근접 회상9). 반경·출처 상태·시각·다른 보관함·삭제·사용 허용 gate·정렬/최대3개를 검증했다.
- Docker production 빌드 통과, localhost:3018 새 컨테이너 실행 완료.
- `E2E_ORIGIN=http://127.0.0.1:3018 E2E_EXTERNAL_SERVER=1 pnpm test:e2e`: **24/24 통과**. Chrome 휴대폰375×812·태블릿1024×768·데스크톱1440×900. 각8개 시나리오.
- 사진 선택→로컬 저장→확대/Escape 초점 복원→새로고침→다른 일기 격리→삭제→재열람 검증. 저장 사본은 image/jpeg이며 업로드 POST/PUT/PATCH 요청이 없음을 확인했다.
- 가짜 PNG(SVG),10MB 초과,8장 초과 요청을 거절하고 기존 사진을 유지했다. IndexedDB 쓰기 트랜잭션을 의도적으로 중단시킨 뒤 오류 표시·기존 사진 유지·재시도 성공·새로고침을 검증했다.
- 재방문 링크→예전 차량/일기→전체 녹음 열기→사용자 구간 재생, 위치 없음/근처 기록 없음 상태를 확인했다. 기존 타임라인·차량별 조회·기간/검색 회귀 포함.
- 최초 실행은 사진 오류 role=alert와 Next.js route announcer가 동시에 선택되어3개 테스트가 실패했다. 사진 영역으로 선택자를 좁힌 뒤24개 모두 통과했다.

## 남은 범위

사진 서버 업로드·인증·양쪽 기기 공유·백업·전체 세션 삭제 연동은 T044/T045의 후속 범위다. 이 브라우저 데이터 삭제나 브라우저 저장소 정리 시 사진이 삭제될 수 있다. origin이 다르면 같은 기기에서도 공유되지 않는다. 사용자에게 사진 영역에서 이 제한을 표시한다.

실제 iPhone/iPad Safari와 HEIC 변환·EXIF 방향의 실기기 조합, 실제 차량 SDK 좌표/정확도/주차 판정, 인증된 회상 API는 미검증이다. 현재 위치를 요청하지 않으며 샘플 녹음 시점 좌표를 쓴다. 웹의 enabled=true는 합성 미리 보기 가정이며 실제 차량 주차 상태의 증거가 아니다. 실제 차량에서는 주차 확인/상실 중단 정책에 연결해야 한다.
