# 로컬 실행·제출 패키지·클라우드 전환

상태: 로컬/제출 구현 / 클라우드는 계획. 정리일: 2026-11-13. 작업 브랜치: dev.
이번 문서는 사용자 승인에 따라 기존 구현·기록을 사후 분리했다. 구현 전에 작성된 명세라고 주장하지 않는다.
이전 식별자: C021, C034~037. [전체 색인](../README.md), [이전 명세](../archive/2026-11-13-before-split/spec.md).

## 사용자 가치와 수용 시나리오

1. 새 환경에서 실행 안내로 APK와 서버를 띄우고 가족 연결/원본/사진을 확인한다. stop/up 후 자료가 남고 배포 ZIP은 비밀을 포함하지 않는다.
2. ZIP의 소스 커밋·APK 버전·파일 해시가 일치하며 구현/목업/미검증 범위가 구분된다.
3. 맥북 기본 Compose 서버(8443)를 쓰는 제출용 앱도 별도 팀 서버를 만들지 않고 주소·공개 CA를 등록한다. 소스 변경 후 재빌드한 서버가 최신6자리 연결 화면을 실제로 제공하는지 확인한다.

## 현재 요구사항

- **DEP-001**: 서버는 Docker Compose·PostgreSQL·Better Auth·비공개 미디어 볼륨을 사용한다. 컨테이너 정지/재시작은 볼륨을 보존하며 백업 완료와 동일시하지 않는다.
- **DEP-002**: Windows 팀원은 Node24 실행 도구와 Docker Desktop Linux 컨테이너, 별도 공식 Pleos 에뮬레이터로 실행한다. 개인 비밀·가족 데이터·개발자 SDK/AVD를 전달하지 않는다.
- **DEP-003**: contestRelease는 서명·debuggable=false·에뮬레이터 한정 앱이다. 서버 없이 녹음→목업→저장→원본/TTS가 동작한다. 주행 모의 기능이 실차 승인 근거가 되지 않는다.
- **DEP-004**: 로컬 테스트 차량은 PC의 HTTPS 주소와 공개 CA를 등록한 뒤 가족 코드로 연결한다. PC configure-release/직접 입력/선택적 파일 경로를 제공한다. 설정 적용 전 주소를 확인하고 연결된 앱의 다른 CA 교체를 막는다.
- **DEP-007**: 기본 `.env.runtime`/`compose.yaml` 환경은 해당 서버의 주소·공개 CA를 contest 앱에 전달하는 실행 명령을 제공한다. 팀 환경의 `.env.team`/18443·CA와 혼용하지 않는다. 해당 CA로 HTTPS 응답을 검증한 뒤 현재 에뮬레이터 사용자에게 확인창을 연다. 실제 적용/페어링 완료는 구분하며 앱 기록·기존 연결·DB/미디어 볼륨·비밀을 초기화하지 않는다. 업데이트 안내는 이미지 재빌드와 단순 재시작을 구별한다.
- **DEP-005**: 제출 ZIP에는 해당 커밋 소스·서명 APK·실행 안내·검증 범위·해시를 담고 비밀/실제 자료는 제외한다. 바탕화면 제출 폴더에는 최신 최종 ZIP만 유지한다. 지원서/동의서 최종본은 별도다.
- **DEP-006**: 계획: 운영 앱은 고정 HTTPS 도메인과 시스템 공인 CA 신뢰를 사용하고 일반 사용자에게 서버 설정을 요구하지 않는다. DB·미디어·기기 인증 이행과 복원 검증을 포함한다. 현재 로컬 CA 코드에서 주소만 바꿔 완료됐다고 표시하지 않는다.

- **DEP-008**: 최초 설치와 기존 환경의 업데이트·재실행을 안내 첫 부분부터 구분한다. `init`은 `.env.team`뿐 아니라 기존 팀 데이터 볼륨을 확인하며, 기존 볼륨이 있거나 Docker 조회가 실패하면 새 비밀을 생성하지 않는다. 기존 설정 분실/DB 인증 실패는 이유와 상태·로그 조회 방법을 알린다. 자동 초기화·비밀번호 변경을 하지 않는다. 사용자가 초기화를 선택한 경우에만 팀 DB/미디어/목업 데이터 삭제 방법을 안내하며 공개 CA 볼륨과 현재 설정은 보존한다. 초기화 후 재가입·재연결과 이전 공유 사본 정리 가능성을 설명한다.
