# 제품 결정 이력

## 2026-11-08 — SDD와 첫 제품 범위

- 사용자 요청: GitHub spec-kit으로 SDD를 적용하고 GitHub 저장소를 만든다.
- 추가 지시: 구현에 앞서 타깃·해결할 문제·베스트 시나리오를 정한다.
- 사용자 결정: 시간이 지나 다시 일기를 읽을 때 STT에 사용했던 원본 녹음도 재생한다.
- 사용자 결정: 차량과 휴대폰 양쪽의 다시 보기·듣기를 첫 버전에 포함한다.
- 작업 기준: 초등학생 자녀가 있는 자동차 나들이 가족, 기록을 주도하는 부모,
  방문 후 주차된 차에서 구성원별 짧은 발화. 이 세부 타깃은 검증할 가설이다.
- 범위 변경: 기존 기획의 원본 음성 보관 제외·기기 동기화 후속 항목을 폐기한다.
- 개발 영향: 음성 입력과 원본 보관의 연결, 보호자 보관함·기기 연결,
  동기화·재생·접근 제한·삭제를 첫 명세에 포함한다.
- 현재 단계: 제품 정의·헌장·기능 명세. 기술 스택 확정·앱 구현은 아직 수행하지 않는다.

## 2026-11-08 — 자유 발화와 LLM 분류·정제

- 사용자 수정: 차에 타서 오늘 일을 짧게 말하는 형식에 제한하지 않는다.
  이것저것 이야기하면 분류와 정제는 LLM이 맡는다.
- 폐기: 한마디·20~30초 권장 발화, 한 장소를 입력 단위로 고정, 발화별 사전 확인 흐름.
- 현재: 여러 장소·사건·시점·정정이 섞인 세션을 입력받고 사건별 초안을 묶음 검토한다.
- 유지: 가족 중심 초기 타깃, 명시적인 녹음, 주차 사용, 수동 발화자 선택,
  원본 음성 보관, 양쪽 기기 재생. 자동 화자 식별·상시 녹음은 추가하지 않는다.
- 보존: 정리에서 생략한 말도 원본에 남기고 관련 음성 구간으로 이동할 수 있게 한다.
- 측정 변경: 전체 발화 시간을 줄이는 대신 사전 분류 없이 완료하는지와
  발화 종료 후 사용자의 정리·검토 조작 시간을 본다. 생성 대기는 별도로 보고한다.
- 헌장: 원칙 VI 추가로 1.1.0. 아직 모델 실행·긴 음성 처리 검증을 수행하지 않았다.

## 2026-11-08 — 구현 계획과 작업 목록

- 다음 단계 요청에 따라 plan·research·data-model·contracts·quickstart·38개 tasks를 작성했다.
- 차량은 Kotlin Android, 휴대폰은 Next.js 모바일 웹으로 계획한다. 첫 범위의 읽기·듣기를 모두 유지한다.
- 보관은 Supabase Auth/Postgres/private Storage, 생성은 별도 작업자의 구조화 출력으로 계획한다.
- OpenAI Responses 초기 평가 후보는 gpt-5.6-terra이며 실제 계정 접근·품질·비용은 미검증이다.
- 차량 원본 녹음·검증된 주차 상태는 실제 G0~G2 통과 조건이다. 원본 캡처 경로를 확인하지 못했다고
  텍스트 전용으로 범위를 축소하지 않는다.
- 앱 코드·실제 SDK 실행·유료 자원 생성·배포는 이 단계에서 수행하지 않았다.

## 2026-11-08 — Docker Compose 프로토타입으로 전환

- 사용자 결정: Supabase를 사용하지 않고 Docker로 구성하며 이후 클라우드로 이전한다.
- 이전 Supabase Auth/Postgres/private Storage 선택을 대체한다. 첫 제품 범위와 헌장은 유지한다.
- 실행: 단일 호스트의 Compose web·worker·Postgres·Caddy, 개발용 Mailpit, 일회성 migrate.
- 인증: Better Auth의 이메일·비밀번호·검증·재설정·DB 세션. 차량 토큰은 기존 별도 연결 방식 유지.
- 저장: DB와 원본을 영속 볼륨에 두고 AudioStore 인터페이스로 로컬 파일 구현을 분리한다.
- 이전: 같은 이미지의 클라우드 실행, 필요 시 관리형 PostgreSQL·객체 저장 adapter 전환.
  데이터·인증 ID·원본 checksum·삭제 표식의 백업/복원·이전 검증을 포함하며 자동 이전을 주장하지 않는다.
- 영향: plan/research/data-model/HTTP·runtime 계약/quickstart/tasks와 도식3종을 갱신한다.
  T039 실행 환경과 T040 복원 검증을 추가해 총40개 작업, 전부 미실행이다.
- 이번 작업은 설계 변경이다. Compose 파일·컨테이너·앱 구현이나 배포는 아직 하지 않았다.

## 2026-11-08 · 시간순 보관함과 전체 녹음 타임라인

- 사용자 결정: 바다/공원/카페 같은 장소별 분류를 기본 탐색에서 없앤다. ‘원래 이야기’에서 전체 녹음을 들으며 구간을 선택하면 해당 시점부터 이어 듣는다.
- 구현 선택: 보관함을 기록 연월별로 묶고 기간 선택·검색을 제공한다. 장소는 기록의 메타데이터와 검색 대상으로 유지한다.
- 재생: 하나의 전체 녹음 플레이어와 시간순 발화 목록을 연결한다. 현재 구간을 표시하고, 구간 선택은 해당 시작점으로 이동 후 전체 녹음 끝까지 재생한다. 가족별 기억의 듣기 버튼도 같은 플레이어로 연결한다. 탭을 떠나거나 재생을 종료하면 멈추고 임시 음성 URL을 해제한다.
- 범위: 웹 합성 미리 보기에 먼저 반영한다. 인증·실제 음성·다중 원본 파일 manifest를 연결하는 T025~T028의 완료를 의미하지 않는다.

## 2026-11-08 · 차량 기억과 녹음 위치

- 사용자 결정: 일기에 차종·모델·차 번호와 차량 위치를 남긴다. 후속 지시로 위치를 녹음 시점으로 고정했다. 구현에서는 녹음 시작 시점을 기준으로 삼는다.
- 차 별명/제조사/모델/차종/연식/선택적 번호를 당시 값으로 복사해 보존한다. 차 교체나 프로필 수정으로 옛 일기를 덮어쓰지 않는다.
- 위치는 이야기 속 방문지가 아닌 ‘녹음을 시작한 곳’이다. 생성·수정·휴대폰 열람 위치로 갱신하지 않는다. 위치가 없거나 오래되면 미확인 상태로 보존한다.
- 헌장 1.2.0: 차량/녹음 위치 기억 보존 원칙을 Product Constraints에 추가했다.
- 첫 UX 확장: 차량 정보 카드·녹음 위치 카드·이 차의 추억 모아보기. 주행/주차·실제 원본 캡처 제약은 유지한다.
- [SDK 근거와 후보 우선순위](research/vehicle-memory.md). 자동 차량 정보·위치 연동은 별도 미검증이며 합성 미리 보기로 완료 처리하지 않는다.

## 2026-11-08 · 수동 사진 첨부와 재방문 회상

- 사용자 승인: 일기에 사진을 직접 추가하고 ‘다시 온 곳, 그때의 목소리’를 구현한다. 사진 자동 수집은 계속 제외한다.
- 사진은 휴대폰/웹에서 선택해 일기에 첨부하고 양쪽 기기에서 보는 것이 제품 범위다. 현재 미리 보기는 인증된 서버가 없어 브라우저 IndexedDB에만 저장하며 기기 공유/백업 완료를 주장하지 않는다. 재시작·삭제까지 실제 로컬 저장 흐름을 제공한다.
- 최초 미리 보기 한도: 일기당8장, 파일당10MB, JPEG/PNG/WebP. 브라우저 디코딩 후 최대2048px JPEG 사본으로 저장한다. HEIC 지원/서버 변환은 후속 검증한다. 원본 사진 파일은 수정하지 않는다.
- 재방문은 녹음 시작 위치 좌표에서 반경300m 이내의 **더 오래된 같은 보관함 기록** 최대3개를 보여준다. 이름 일치로 장소를 추정하지 않는다. 차가 달라도 같은 가족의 이전 기록은 포함한다. 300m는 초기 제품 선택이며 정확한 같은 장소 방문을 증명하지 않는다.
- 위치 없음/미지원/stale/좌표 없음이면 재방문 결과를 생성하지 않는다. 차량은 주차 확인 시에만 제공하며 자동 재생·배경 위치 추적을 추가하지 않는다. 사용자가 과거 기록을 선택하면 전체 녹음 플레이어를 연다.
- 헌장1.3.0, FR-018/019, T044~T046 추가. 실제 SDK 위치/주차·사진 서버 저장·기기 동기화는 미완료로 유지한다.
