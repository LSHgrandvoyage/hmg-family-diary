# C045 재생 통합·날짜순 목록·실시간 인식 흐름

2026-11-13. [002 REC-007/008](../../specs/002-voice-diary/spec.md), [004 PLAY-011/012](../../specs/004-memory-playback/spec.md), [006 UX-010](../../specs/006-vehicle-experience/spec.md). 헌장2.4.0과 각 spec → plan → tasks → 정합성 검토를 먼저 작성한 뒤 구현했다.

## 결과

1. 주행과 주차 하단 플레이어에 이전/재생·일시정지 토글/다음, 같은 일기의 `일기 읽어주기`/`그날의 목소리` 전환을 연결했다. 주차 X는 명시적 종료다. 멈춘 상태의 이전/다음/방식 전환은 자동 재생하지 않는다. 재생 중 전환은 기존 음성 종료 확인 뒤 시작한다.
2. 원본은 실제 MediaPlayer 위치부터 재개한다. Pleos TTS3.3.1에 직접 pause/seek API가 없어 문장 단위로 speak하고 stop 응답을 확인해 현재 문장을 보관한다. 재개는 해당 문장 처음부터이며 일기 전체를 다시 시작하지 않는다. 매우 긴 무구두점 문장은 최대240 code point로 나누고 문자를 누락하거나 surrogate pair를 쪼개지 않는다. UI 버튼 도움말에 문장 단위 재개임을 표시한다. 경과시간은 실제 낭독 상태의 시간이며 일시정지 동안 흐르지 않는다. 전체 길이/진행률을 추측하지 않는다.
3. 주행 오른쪽은 날짜 오름차순의 전체 완성 일기 제목·날짜 목록이다. 최초 현재±8개(최대17개), 이후 이전/다음 커서로8개씩 가져온다. 로컬 차량의 메타데이터 bridge 페이지이며 새 클라우드 목록 API는 아니다. 보유 데이터가4개면4개 모두 포함한다. 현재 항목은 테두리/듣는 중/aria-current로 구분하며 누르면 해당 일기를 현재 방식으로 재생한다.
4. 앞쪽 삽입은 기존 스크롤 위치를 유지하며, 중복 ID·목록 끝·로딩·오류 재시도·갱신 중 늦은 응답을 처리한다. 날짜/ID 순서를 native가 소유한다. 커서가 삭제되거나 목록 세대가 바뀌면 현재 일기 중심으로 재설정한다. 본문·사진·전체 인식문을 목록 응답에 넣지 않는다. 동기화/목록 갱신 후 메타데이터 캐시도 무효화한다.
5. 주행 STT는 SDK의 실제 최근 인식문을 명시적 개행과 폰트/화면 폭으로 나누어 마지막2줄을 표시한다. 현재 줄은 기존 글자색, 이전 줄은 opacity0.68이며 세 번째 줄이 생기면 가장 오래된 줄이 사라진다. 부분 인식 수정·긴 무공백 텍스트·폰트 로딩/폭 변경도 갱신한다. 마이크 수집·PCM·STT SDK 경로는 바꾸지 않았다.
6. 기존 주차 화면의 최근4문장 제한을 제거했다. 전체 인식문을 스크롤 영역에 보존하고 최신 위치를 따라간다. 사용자가 위로 이동하면 강제 이동을 멈추며 `최신 문장으로`로 복귀한다. 화면이 가득 차도 원본과 인식문 저장이 잘리는 구조가 아니다. 차량 일기 탭의 `일기 N편 이어 듣기` 버튼은 제거했다.

- 공식 Pleos 에뮬레이터 `emulator-5580` 사용자10에서 `DrivingListenDeviceTest`와 `WelcomeDeviceTest`를 실제 실행했다. **2개 통과, 건너뜀 없음**. cache 전용 UUID 합성 기록41개로 native 페이지와 삭제 커서 재설정을 검증했다. 실제 SDK가 두 번째 문장을 낭독할 때 일시정지 → 종료 응답 → 시간/문장 유지 → 같은 문장 재개를 확인했다. 같은 파일의 원본으로 전환, 원본 pause, 일시정지 상태 다음 일기·방식 전환의 미재생, 명시적 선택 재생, 종료 후 늦은 자동 재개 없음도 통과했다.

## 빌드·실행 상태·남은 범위

`io.hmg.familydiary.contest`, contestRelease **0.2.7 / versionCode8**. APK SHA256: `724e50ba0bbc1a54a80b14bc2d1400a225c8ef42d5a3a96503707992ec1f40e7`. 최종 커밋과 ZIP 해시는 제출 묶음의 manifest/SHA256SUMS가 정본이다.

이번 검증 직전 Docker와 에뮬레이터는 정지 상태였다. 검증용으로만2코어·화면/호스트 오디오 없는 에뮬레이터와 기존 Compose를 임시 실행했다. 최신 APK는 기존 설치에 덮어 설치했고 DB/비공개 미디어 볼륨과 연결을 지우지 않았다. 종료 후 두 환경을 다시 정지시켰으며 caffeinate를 시작하지 않았다. 최신 Docker 이미지는 다음 실행에 사용할 수 있다. 네트워크 주소 설정은 이번 기능 작업에서 변경하지 않았다.

STT UI가 한 줄을 채운 뒤 새 글을 표시하지 못하는지 합성 인식 갱신·긴 문장·개행으로 검증했다. 실제 마이크의 새 인식 결과가 멈춘 원인을 마이크 품질로 단정하거나 실제 음성 인식 정확도를 재검증한 것은 아니다. SDK 오류/오디오 입력의 별도 진단이 필요할 수 있다. Windows/iPhone/실차 결과, 주행 중 목록/STT의 마켓 허용, 원본 보관·외부 전송 정책은 이번 에뮬레이터 검사로 입증하지 않는다. 일기 생성은 계속 고정 목업이다.
