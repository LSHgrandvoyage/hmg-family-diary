## 우리 팀의 준비 순서

- [ ] 작성해 둔 1차 지원서에 “고정 목업 일기”와 플랫폼 미확인 범위를 정확히 반영한다.
- [ ] 전원 동의·서명·날짜·연락처를 확인한다. 개인 지원서/동의서는 공개 Git 저장소에 넣지 않는다.
- [ ] Windows 팀원이 [환경 안내](../team/windows-testing.md)로 새 환경에서 시험한다.
- [ ] 합성 대화/테스트 사진으로 짧은 영상: 녹음 → 주차 검토 → 고정 목업 저장 → 자동 동기화 → 사진 → 원본/TTS 청취를 보여 준다. 목업·모의 주행 표시는 숨기지 않는다.
- [X] C035 에뮬레이터용 서명된 `contestRelease` 구현·설치/실행 검증 및 소스 패키징 경로 준비. [실행 안내](release-runbook.md).
- [ ] 원본 취득/보관/전송 지원 근거와 실제 주행 허용은 별도 확정한다. 에뮬레이터 release를 실차/마켓 승인으로 설명하지 않는다.
- [X] 사용자 결정: private 저장소 유지, 제출 커밋의 소스+release APK ZIP을 준비한다. 다운로드 링크 업로드와 접수는 아직 실행하지 않았다.
- [ ] 제출할 커밋을 고정하고 APK 해시·빌드 환경을 기록한다. 이후 dev 작업은 계속해도 제출 커밋을 임의로 바꿔 설명하지 않는다.
- [ ] 공개/압축 제출 경로를 선택하고 다른 PC의 비로그인 환경에서 다운로드·설치를 확인한다.
- [ ] 제목·수신·CC·첨부와 링크 접근을 최종 확인한 뒤 직접 발송한다.
