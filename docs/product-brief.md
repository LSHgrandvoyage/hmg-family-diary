# 가족 여행일기 제품 정의

버전 0.2 · 2026-11-08 · 제품 가설과 첫 개발 기준선

## 제품 한 문장

**차에서 자유롭게 풀어놓은 가족의 이야기를 일기와 실제 목소리로 남겨,
시간이 지난 뒤 차량과 휴대폰에서 다시 꺼내 보는 가족 여행 기록 서비스.**

가치는 세 순간에 생긴다. 기록할 때는 부모의 정리 부담을 줄이고,
완성된 일기를 볼 때는 서로 달랐던 경험을 알며,
나중에 다시 들을 때는 그날의 표현과 목소리까지 떠올린다.

## 1. 첫 타깃

| 구분 | 첫 타깃 정의 |
|---|---|
| 가족 | 초등학생 자녀가 있고 자동차로 주말 나들이·여행을 하는 가족 |
| 행동 | 여행 사진은 자주 남기지만 글·앨범 정리를 미루거나 한 부모만 담당 |
| 시작 사용자 | 기록을 남기고 싶어 하는 부모·보호자. 설치·연결·진행·보관함 관리 담당 |
| 공동 참여자 | 자녀와 동행 가족. 이야기하고 싶을 때 자유롭게 참여. 길이·주제별 발화 형식 강제 없음 |
| 다시 보는 사용자 | 보호자의 휴대폰 또는 주차된 차량에서 기록을 함께 보는 가족 |
| 처음 집중할 상황 | 체험·관람·해변 방문 등을 마친 뒤 차로 돌아와, 출발 전 여유가 있는 순간 |

‘초등학생’은 시장 수요를 확인한 결론이 아니라 초기 검증을 위한 선택이다.
자기 경험을 말로 이야기할 수 있고 부모가 기록을 함께 진행하는 상황을 우선 검증한다.
소유자의 연령·성별·소득이나 자녀의 발달 특성을 추정해 타깃 조건으로 쓰지 않는다.
매일 쓰는 습관보다 **나들이가 있을 때 다시 쓰는 이유**를 먼저 확인한다.

혼자 출퇴근하며 생각을 정리하는 사람, 운전 중 업무 메모가 필요한 사람,
자동 기록만 원하고 말할 의사가 없는 가족은 초기 핵심 타깃에서 제외한다.
커플·친구 여행은 같은 구조로 확장할 수 있지만 첫 검증에 섞지 않는다.

## 2. 해결할 문제

**여행 사진은 남아도 가족 각자가 느낀 것은 빠지고,
이를 글로 정리하는 일은 부모 한 사람에게 몰린다.**

이 문제는 다음 세 가설로 나눠 검증한다.

1. **기억의 누락:** 귀가 후 적으려 하면 아이의 정확한 표현과 각자의 생각을 잊는다.
2. **기록 부담의 편중:** 한 사람이 가족에게 물어보고, 받아 적고, 글을 정리해야 한다.
3. **회상의 부족:** 정리된 글만으로는 당시 말투와 목소리를 다시 경험하기 어렵다.

가족이 사진·영상만으로 충분하다고 느끼거나, 녹음 참여를 번거롭게 느끼면 이 가설은 약해진다.
기존에 잘 해결하고 있는 가족에게 일기 작성 문제를 만들어 설명하지 않는다.

## 3. 사용자가 하고 싶은 일

> 차에서 가족과 이런저런 일을 이야기할 때, 말할 순서나 분류를 미리 정하지 않아도
> 앱이 장소·시점·주제와 각자의 기억을 정리해 주고 원래 목소리도 남겼으면 좋겠다.
> 나중에는 가족과 일기를 읽다가 그때 한 말을 그대로 다시 듣고 싶다.

입력 단위는 **자유로운 이야기 세션**이다. 한 세션에 여러 장소·사건·시점과 잡담이 섞일 수 있다.
사용자는 먼저 분류하거나 장소별로 녹음을 끊을 필요가 없다.
LLM이 사건·장소·시점·주제를 묶고, 선택된 발화자 정보를 이용해 사람별 기억과 공동 일기를 만든다.
장소·날짜별 카드는 정리 결과이며 입력 양식이 아니다. 순서나 장소가 불분명하면 미정으로 둔다.
정리된 기억에는 원본 녹음과 근거 구간을 연결하고, 요약에서 빠진 말도 원본에서 다시 들을 수 있다.

## 4. 베스트 시나리오

아래는 설계를 위한 합성 사례이며 인터뷰 결과가 아니다.

**상황:** 부모와 초등학생 자녀가 해변을 둘러보고 차에 돌아왔다.
차는 주차 상태이고 곧바로 출발할 필요는 없다. 보호자의 휴대폰은 가족 보관함에 연결돼 있다.

1. 부모가 ‘이번 바다 나들이’에서 녹음을 시작한다. 장소·주제를 먼저 고르지 않는다.
2. 아빠가 자신을 선택하고 “오늘 바다 좋았어. 가기 전에 식당에서 먹은 점심도… 아, 아침이었지. 생선구이가 맛있었어. 어제 카페는 너무 시끄러웠고. 아 맞다, 충전 케이블 챙겨야겠다.”처럼 생각나는 대로 말한다.
3. 민지는 자신을 선택하고 “바다 파도가 커서 무서웠어. 근데 조개 줍는 건 재밌었어.”라고 보탠다.
4. 녹음을 끝내면 LLM이 오늘의 식당·해변, 어제의 카페, 여행 사건과 무관한 메모를 구분한다. 사용자가 장소별로 다시 입력할 필요는 없다.
5. 명시적인 정정에 따라 식사를 아침으로 정리하고, 어제 카페 이야기는 오늘 일기에 섞지 않는다. ‘식당’의 실제 이름이나 정확한 방문 순서는 근거가 없으면 추정하지 않는다.
6. 부모는 사건별 초안과 사람별 기억을 한 번에 검토한다. 잘못 묶인 내용·불확실한 장소·인식 오류를 필요할 때 고친다. 발화마다 문장을 미리 정리할 의무는 없다.
7. 두 감정을 유지한 일기와 원본 음성을 저장한다. 빠진 내용도 추가할 수 있다.
8. 일기와 두 원본 녹음이 보관된다. 아직 전송 중이면 ‘이 차량에 저장됨’과
   ‘휴대폰에서도 볼 수 있음’을 구분해 보여준다.
9. 일주일 뒤 집에서 보호자의 휴대폰으로 그날 기록을 찾는다.
   기록 연월별 보관함에서 일기를 열고, 민지의 기억 옆 재생 버튼을 눌러 전체 녹음의 관련 시점부터 듣는다.
   전체 녹음과 원문 구간을 함께 보며 원하는 구간으로 이동하고, 구간 끝에서도 끊지 않고 이어 듣는다.
10. 다음 나들이에 주차된 차에서도 같은 기록을 열고 듣는다.

**첫 사용의 성공 순간:** 두서없이 말해도 사용자가 직접 분류·정리하지 않고 여러 사건과 가족의 관점이 정돈된 초안을 얻는다.
**다시 찾는 이유:** 시간이 지나도 그날의 아이 목소리와 다른 가족의 기억을 함께 꺼낼 수 있다.
‘다음 여행에서도 사용한다’는 행동은 실제 후속 관찰 전까지 가설이다.

## 5. 차량에서 시작해야 하는 이유

차는 방문이 끝난 가족이 다시 모이는 장소이며, 기록할 시점을 일정하게 만들 수 있다.
차량 화면·마이크·주차 맥락을 활용해 한 사람이 휴대폰을 전달하며 기록하는 부담을
줄일 수 있다는 것이 우리 가설이다. 귀가 후 회상은 휴대폰에서 이어진다.

스마트폰 녹음기와 AI 일기 앱으로도 유사한 일을 할 수 있다.
따라서 차량이 없으면 불가능하다고 주장하지 않는다.
같은 가족이 두 방식을 써 보고 **준비 시간·참여 인원·정리 부담**에서 차이를 느껴야 한다.
차량 마이크가 뒷좌석을 잘 받지 못하거나 출발이 늦어져 부담이 커지면,
차량 환경이 장점이라는 가정을 재검토한다.

## 6. 기존 대안과 우리가 입증할 차이

| 대안 | 이미 잘하는 일 | 우리가 검증할 차이 |
|---|---|---|
| 사진·가족 영상 | 장면과 당시 모습을 보존 | 여러 이야기에 섞인 가족의 느낌을 사건별로 모아 다시 찾기 |
| 휴대폰 음성 메모 | 목소리 원본 보관 | 발화자·장소·일기를 연결해 어떤 녹음인지 알아보기 |
| [컬로그](https://callog.gkuer.com/) | 말한 내용을 AI 일기로 정리 | 여러 가족의 관점을 한 방문에 보존 |
| [RoadNotes](https://www.roadnotesapp.com/) | 차량에서 음성을 텍스트·요약으로 기록 | 여행의 공동 회상과 원본 목소리 재방문 |
| [Auricle](https://auriclejournal.com/) | 공식 소개상 차량 음성 일기 | 한 가족 여러 사람의 기억·장소·공동 기록 흐름 |
| [Remento](https://help.remento.co/en/articles/8365951-how-do-i-record-a-memory) | 목소리로 가족의 이야기를 글로 남기기 | 차량 내 자유로운 이야기의 사건별 정리와 차량·휴대폰 연결 |

공식 소개를 기준으로 한 비교이며 앱 설치·경쟁 제품 전체 기능 검증은 하지 않았다.
‘차량 음성 일기 최초’나 ‘가족 음성 기록 최초’를 차별점으로 내세우지 않는다.

## 7. 첫 버전에서 완결할 범위

**반드시 포함:** 차량에서 명시적 녹음, 구성원 선택, 인식문 확인,
여러 사건·장소·시점의 자동 분류와 정제, 필요 시 정리 결과 수정, 개인별 기억·공동 일기, 원본 음성 보관,
가족 보관함 기기 연결, 차량·휴대폰의 기록 목록·읽기·재생,
동기화 상태·재시도·삭제.

**후속 범위:** 자동 화자 구분, 동시 대화 자동 분리, 사진 자동 수집·영상,
여행 경로 지도, 인쇄 책, 여러 보호자의 개별 계정, 공개 공유,
휴대폰에서 새 음성 일기 작성, 운전 중 기록·열람·재생.

원본 음성과 양쪽 기기 재생은 사용자 결정에 따라 첫 버전에 포함한다.
이를 구현하기 어렵다는 이유로 텍스트만 보관하는 기능으로 조용히 축소하지 않는다.
이전 기획의 ‘음성 영구 보관 제외’와 ‘기기 동기화 후속’은 폐기된 범위다.

## 8. 성공 기준과 검증

모든 수치는 **목표**이며 현재 관측된 실적이 아니다.

| 질문 | 관찰 방법 | 초기 판단 기준 |
|---|---|---|
| 정리 부담이 줄었는가? | 초기 연결을 마친 가족 5팀이 여러 사건을 자유롭게 말함 | 4팀 이상이 사전 분류 없이 완료하고, 말하기 종료 후 검토·저장에 쓴 능동 조작 시간이 2분 이내. 발화·생성 대기·최초 설정 시간은 각각 별도 보고 |
| 다른 관점이 유지되는가? | 서로 반대되는 감정이 있는 사례 포함 | 준비한 충실도 검증 사례 모두에서 감정 전이·새 사건 생성 0건 |
| 나중에 찾고 들을 수 있는가? | 저장 후 차량·휴대폰 양쪽에서 찾기 | 5팀 중 4팀 이상이 날짜·장소로 30초 내 목표 원본 재생 시작 |
| 차량의 이점이 있는가? | 같은 가족이 휴대폰 녹음·정리 방식과 비교, 순서 교대 | 5팀 중 3팀 이상이 구체적인 준비·참여·정리 이점을 설명. 단순 호감 제외 |
| 다시 쓸 이유가 있는가? | 다음 실제 나들이가 있었던 가족만 후속 관찰 | 재사용 가족 수/다음 나들이가 있었던 가족 수를 기록. 표본 없이 유지율 주장 금지 |

3가족의 문제 인터뷰부터 시작해, 문제가 확인되면 5가족 사용성 검증으로 이어간다.
이는 작은 탐색 표본이며 시장 규모·통계적 효과의 증거로 사용하지 않는다.
부모의 정리 부담이나 재청취 욕구가 관찰되지 않으면 기능 추가보다 타깃·문제를 수정한다.

## 차량과 함께 보존하는 기억 — 2026-11-08 확장

그날 탔던 차의 별명·제조사·모델·차종·연식·선택적 번호와 **녹음 시작 시점의 차량 위치**를 일기에 붙인다. 차가 바뀌거나 번호가 바뀌어도 예전 기록은 당시 값을 유지한다. ‘이 차의 추억 모아보기’는 차량 ID를 기준으로 하며 월별 기록 구조를 유지한다. 녹음 위치와 이야기 속 방문지는 별개다. 실제 SDK 연동 전 웹 미리 보기에는 가상 차량·장소만 사용한다.

## 사진과 재방문 회상 — 2026-11-08 확장

보호자가 휴대폰/웹에서 선택한 사진을 일기에 첨부하고 양쪽 기기에서 다시 볼 수 있다. 차량에서는 사진 파일 선택·첨부를 제공하지 않는다. 사진 내용으로 발화에 없는 사실을 자동 생성하지 않는다. 녹음 시작 위치 주변에서 과거에 남긴 가족 기록을 찾고, 이전 차에서 남긴 기록도 포함해 사용자가 당시 목소리를 듣는다. 사진 EXIF 위치나 휴대폰 열람 위치로 녹음 장소를 바꾸지 않는다. 미리 보기의 사진은 같은 브라우저/같은 주소에만 보관되며 서버·기기 간 동기화와 구분한다.

## 2026-11-11 제품 정책 변경 — C019

사용자 요청으로 첫 버전의 주행 중 음성 녹음/원본 청취를 목표 범위에 추가한다. 주행 화면은 녹음 시작/일시정지/종료와 선택된 원본 재생/일시정지·이전/다음으로 축소한다. 사진·전사문·일기 본문·문장 수정·검토·계정/차량 설정은 주차 후 제공한다. 주행 중 종료한 녹음은 검토 대기로 보관하고 주차 후 같은 원본/인식문으로 이어간다. 신호 대기 속도0은 검토 허용 조건이 아니다. 실차 카테고리/주행 UX·마이크 허용은 아직 확인 전이며 현재 개발 범위는 명시적 에뮬레이터 모의 모드다. 자동 음성 명령 시작과 백그라운드 지속 녹음은 별도 범위로 남긴다.


## C020 — 내비와 함께 기록하기
사용자가 시작한 녹음은 내비로 전환하거나 Activity가 재생성되어도 foreground microphone service에서 이어간다. 차량 상태·동의·오디오 사용 가능 여부는 계속 감시한다. 서버 변경은 SSE 알림과 cursor 조회로 받고 주기적/느린 데이터 폴링은 제거한다. 녹음 화면은 Downloads의 `차량 · 녹음 중@1x.png`를 따른다. 실제 화자 자동 분리나 자동 서버 음성 저장은 표시하지 않는다.

## C021 공모전 보완

녹음 시작 직전 공식 SDK 관측을 위치 스냅샷으로 보관하며, 사용자가 위치 권한을 거절해도 녹음할 수 있다. 원본과 공식 TTS 청취는 화면과 독립적인 미디어 서비스로 유지한다. 차량·휴대폰의 차량 필터는 기록 당시 스냅샷을 기준으로 한다. 식별 가능한 차량 ID가 없는 이전 기록을 같은 실제 차량이라고 추정하지 않으며, 별칭/모델/번호 등이 달라진 스냅샷은 별도 항목으로 표시한다. 현재 프로필로 과거 기록을 덮어쓰지 않는다.

자동차는 일기의 서술 화자다. 실제 센서로 보지 못한 사건을 보았다고 쓰거나 가족의 감정을 자동차의 감정으로 바꾸지 않는다. 현재 생성 목업은 유지하며 v4의 실제 문장 품질은 별도 실험한다.

## C022 보고서 기획 보완

사용자가 주간·밝은 환경 라이트, 야간·터널 등 어두운 환경 다크 전환을 제품 방향으로 정했다. C024에서 차량 시스템의 주야간 설정과 모바일 시스템 테마를 따르는 자동 전환 및 수동 선택을 구현했다. 실차의 터널·조도 신호 전달은 별도 검증 대상이다.

사용 시나리오는 (1) 자유로운 대화의 기록 부담 감소 (2) 자동차 화자의 서술을 통한 친밀감 (3) 주행 중 최근 일기의 TTS 플레이리스트 청취 (4) 과거 차량을 단서로 어린 시절 원본 목소리 회상으로 나눈다. 주행 TTS 시작·이전/다음과 정상 종료 후 목록 내 연속 재생은 추가 구현 대상이다. 포커스/차량 상태 상실 뒤 자동 재개 금지는 유지한다.

이 시점의 최초 공유 정책은 후속 C023 자동 동기화로 대체한다.

## C023 사용자 확정 — 완성하면 자동 동기화

C022의 개선 제안은 사용자 승인으로 확정 계획이 됐다. 같은 가족 보관함에 연결한 뒤 최종 저장한 일기와 원본·차량 맥락을 자동 동기화하며 일기마다 공유 버튼을 요구하지 않는다. 미확정 초안은 로컬에 남기고, 오프라인 완성본은 영속 전송 대기열에서 보존해 연결 복구 후 재시도한다. 최초 연결 전 완성본도 연결 안내 범위에 포함하되 다른 보관함 소유 기록은 자동 이관하지 않는다. 연결 해제·만료·삭제가 업로드보다 우선한다.

사용자는 동기화 대기/중/완료 및 연결 필요를 확인한다. 서버 변경의 기기 적용은 주차·유휴에 수행하고 신호 대기·단순 정차를 주차로 해석하지 않는다. 앱/차량 전원 종료 중 즉시 동기화를 약속하지 않는다. 프로토타입의 C023 자동 업로드를 구현했다. 충돌한 일기는 자동 덮어쓰지 않고 기기에 보존하며 확인 필요 상태로 표시한다. 실차/강제 종료 중 즉시 실행을 보장하지 않는다.

차량 및 모바일 웹의 라이트/다크 자동 전환·수동 선택은 C024에서 완료했다. 다음 구현은 TTS 플레이리스트다.


## C024 검색·필터와 화면 모드

차량과 모바일의 일기 목록에서 검색어와 기록 당시 차량 조건을 하나의 ‘검색·필터’ 패널에서 적용·초기화한다. 모바일 소개 제목은 제거한다. 화면은 자동/라이트/다크 중 기기별로 선택하며, 차량 설정과 모바일 가족 → 화면 설정에서 변경한다. 차량은 Android uiMode, 모바일은 시스템 색상 설정을 따른다. 전환은 표시 색상만 갱신해 녹음·청취·수정 중 입력을 유지한다. 차량의 주행 중 검토 제한은 그대로 적용한다. 실차 터널 감지와 iPhone Safari 실기기 검증은 미완료이며 에뮬레이터·독립 브라우저 검증으로 대신 주장하지 않는다.


## C025 차량 일기 TTS 플레이리스트

차량 목록에서 검색·차량 필터에 맞는 완성 일기를 최신순으로 이어 듣는다. 목록은 시작 순간 고정하며 마지막에서 종료한다. 상세의 한 편 읽기와 전체 원본 듣기는 별도 기능으로 유지한다. 주행 화면에는 완성 일기 듣기/이전/다음/종료를 제공하고 본문·사진·복잡한 목록 선택은 주차 후에만 제공한다. 내비게이션 전환에도 사용자가 시작한 재생을 이어가며 상태 불명·포커스 상실·사용자 종료·엔진 오류 후에는 자동 재개하지 않는다. 이번 범위는 공식 Pleos TTS를 사용하는 차량이며 모바일 웹 TTS는 후속이다.


## C026 발언별 원본 타임라인

차량 주차 화면과 모바일 원래 이야기에서 실제 STT 확정 발언 구간을 표시하고, 선택하면 전체 원본의 해당 시점부터 이어 듣는다. 원문 구간은 LLM 일기나 사용자가 수정한 확인문과 별개로 보관한다. 시각이 없는 과거 기록·불확실한 구간은 임의로 나누지 않는다. 화자 분리는 현재 공개 SDK 지원 여부와 별도 로컬 분석 가능성을 검토하며, 자동 가족 실명 식별이나 모델 호출은 이번 구현에 포함하지 않는다.


## C027 화면 복귀·테마 바로 전환·입력 파형
차량 설정을 나와 녹음/일기 탭을 누르면 동일한 디자인의 해당 화면으로 복귀한다. 차량 탐색 영역과 모바일 헤더에서 태양/달 버튼으로 바로 라이트·다크를 바꾸고 자동 모드도 복원한다. 전환은 진행 중인 녹음·재생·수정 내용을 유지한다. 녹음 파형은 실제 입력 크기에 반응하며 무음/일시정지는 조용한 상태로 표시한다.

### C028 사용성 보정 (2026-11-12)
자동 테마의 기준과 현재 색상을 알리고 정보 없는 차량 필터를 하나로 묶는다. 모바일 검색/가족 패널은 상단 X로 닫고 가족 메뉴에서 화면 설정을 제거한다. 일기 듣기 종료는 실제 음성까지 중단해야 한다. 핸들 미디어 버튼과 일기 이전/다음/종료를 연결할 수 있는 범위를 조사하되 로터리/터치패드 실차 호환은 별도 검증한다.

### C029 설정 정리 (2026-11-12)
차량 설정은 휴대폰 연결·우리 차 정보·녹음 위치·화면 모드로 단순화한다. 사용자가 준 설정 PNG의 두 열 카드 배치를 따른다. 개발 진단·샘플 위치는 노출하지 않고 자동 녹음/안전 해제 기능은 제공하지 않는다. 검색 명칭은 검색으로 통일하며 모바일 화면은 수동 테마만 제공한다.

### C030 차량 탐색 통일
차량 모든 탭은 같은 왼쪽 메뉴와 하나의 자동/라이트/다크 순환 버튼을 사용한다. 설정의 화면 모드 카드는 제거하며 모바일 수동 테마 정책은 유지한다.

### C031 차 별명
차 별명 하나를 차량 프로필과 휴대폰 연결 목록에 사용한다. 과거 일기의 차량 이름은 기록 당시 값으로 유지하고 다음 녹음부터 현재 이름을 남긴다. 연결 별칭이라는 별도 사용자 개념을 제거한다.

### C032 주행 화면과 홈 복귀
제공한 녹음 PNG의 공통 레이아웃을 주행 중에도 사용하되 인식문·사진·일기 본문을 숨긴다. 모드만 전환했을 때는 과거 기록 검토를 자동으로 열지 않고 녹음 홈으로 복귀한다.
