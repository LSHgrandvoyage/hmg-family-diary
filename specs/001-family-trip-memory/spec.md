# Feature Specification: 가족의 여행 기억과 원본 목소리 보관

**Feature Branch**: `main` (초기 명세 기준선; 기능 디렉터리와 Git 브랜치는 독립)

**Created**: 2026-11-08

**Status**: Draft — 제품·기능 기준선, 앱 구현 및 사용자 검증 전

**Input**: 가족 여행 음성 일기. 타깃·문제·베스트 시나리오부터 정의하고,
기록에 사용한 실제 녹음물을 보관해 차량과 휴대폰 양쪽에서 다시 읽고 듣는다.
한마디·짧은 발화·한 장소 형식에 제한하지 않으며 여러 이야기를 LLM이 분류·정제한다.

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 방문 후 가족의 기억을 남긴다 (Priority: P1)

초등학생 자녀와 나들이한 부모가 주차된 차에서 기록을 시작한다.
참여할 구성원을 선택해 자유롭게 말한다. 한 세션에 여러 사건·장소·시점이 섞여도
앱이 분류·정제한 일기를 묶음으로 검토하고 원본 녹음과 함께 저장한다.

**Why this priority**: 한 사람의 정리 부담을 줄이면서 여러 사람의 기억을 남기는 첫 가치다.

**Independent Test**: 두 사람이 식당·해변·어제의 카페 이야기를 순서 없이 말하고
중간에 사실을 정정한다. 사전 분류 없이 사건별 초안을 얻고 서로 다른 감정과
원본 구간 연결을 확인한다. 발화 길이는 검증 입력의 속성이며 사용자 형식 제약이 아니다.

**Acceptance Scenarios**:

1. **Given** 주차가 확인되고 공동 녹음 안내를 확인한 가족,
   **When** 아빠와 자녀가 각각 자신을 선택해 여러 이야기를 말하고 녹음을 마치면,
   **Then** 사전 분류·발화별 확인 없이 사건별 초안이 만들어지고 각 내용이 원래 발화자·녹음 구간에 연결된다.
2. **Given** 아빠는 파도를 좋아했고 자녀는 무서웠다고 말한 기록,
   **When** 일기를 만들면, **Then** 두 관점이 유지되고 ‘모두 즐거웠다’는 결론을 만들지 않는다.
3. **Given** 인식문에 잘못된 단어가 있는 기록,
   **When** 사용자가 문장을 수정하면, **Then** 생성은 수정문을 따르고 원본 녹음은 그대로 보존된다.
4. **Given** 현재 위치가 오래됐거나 이야기 속 방문지와 다른 상황,
   **When** 분류된 사건들의 장소 후보를 검토해 수정하거나 미정으로 두면,
   **Then** 각 사건의 확인된 장소만 저장본에 사용한다. 녹음 전에 장소를 입력할 필요는 없다.
5. **Given** 한 사람만 참여하거나 구성원이 건너뛴 상황,
   **When** 저장하면, **Then** 실제 참여자의 기억만 남고 나머지 사람의 기억을 만들지 않는다.
6. **Given** 녹음에 실패해 원본 음성이 확보되지 않은 발화,
   **When** 저장을 시도하면, **Then** 오류·재시도와 텍스트 임시 보관 상태를 표시하고
   원본까지 완성된 기억으로 표시하지 않는다.

7. **Given** 식당·해변·어제의 카페·잡담을 순서 없이 이야기한 세션,
   **When** 정리하면, **Then** 사건·시점별로 묶고 어제 이야기를 오늘 사건으로 바꾸지 않는다.
   불명확한 장소명·순서는 미정으로 두고 발화자 정보는 선택된 구성원을 따른다.
8. **Given** “점심 먹었어. 아, 아침이었지.”처럼 같은 사실을 명시적으로 정정한 발화,
   **When** 정리하면, **Then** 정정된 아침을 반영하고 원본의 두 표현은 그대로 들을 수 있다.
   명시적 정정이 없는 두 사람의 충돌은 임의로 덮어쓰지 않는다.
   다른 화자가 ‘아니’로 반박해도 합의가 없으면 각자의 문장·근거를 보존하고 제목에서도 정정으로 확정하지 않는다.
9. **Given** 같은 사건을 반복해 말하거나 관련 없는 메모가 섞인 입력,
   **When** 정리하면, **Then** 의미가 같은 반복은 통합하고 다른 관점은 유지한다.
   일기에 포함하지 않은 내용도 원문·원본에서 보며 다시 포함할 수 있다.
10. **Given** 사건별로 정리된 초안,
    **When** 사용자가 잘못 묶인 내용을 옮기거나 분리·합치기·포함 여부를 수정하면,
    **Then** 수정에 맞게 초안을 갱신하고 관련 원본 구간·발화자 연결은 유지한다.

### User Story 2 - 나중에 양쪽 기기에서 읽고 듣는다 (Priority: P1)

부모와 가족이 집에서는 휴대폰으로, 다음 나들이의 주차된 차에서는 차량 화면으로
이전 방문 일기를 찾아 읽고 해당 구성원이 당시 말한 실제 음성을 듣는다.

**Why this priority**: 다시 듣는 순간까지 완결해야 사용자가 선택한 첫 버전의 가치가 성립한다.

**Independent Test**: 음성과 일기가 준비된 보관함으로 시작해 차량과 휴대폰 각각에서
목표 날짜·장소의 기록을 찾고 같은 발화를 재생한다. 새 기록 작성 없이 검증한다.

**Acceptance Scenarios**:

1. **Given** 보호자가 관리하는 보관함과 연결 가능한 차량,
   **When** 보호자가 휴대폰에서 자신의 보관함과 차량의 연결을 확인하면,
   **Then** 해당 차량과 휴대폰은 같은 가족 기록에 접근한다.
2. **Given** 일기·음성이 동기화된 기록,
   **When** 기록 연월별 목록·기간 선택·검색으로 찾고 구성원의 재생을 누르면,
   **Then** 해당 기억의 근거 음성 구간부터 재생되고 전체 녹음도 들을 수 있다.
   전체 녹음 플레이어와 시간순 원문 구간을 함께 보여준다. 구간을 누르면 해당 시점으로 이동해
   재생하며 구간 끝에서 끊지 않고 전체 녹음 끝까지 이어진다. 현재 구간을 강조한다.
   재생·일시정지·탐색·종료할 수 있으며 떨어진 여러 근거 구간은 별도로 표시한다.
   보관함의 기본 묶음은 기록 연월이며 장소는 분류 탭 대신 메타데이터·검색 대상으로 둔다.
3. **Given** 음성이 아직 전송되지 않았거나 내려받기에 실패한 기록,
   **When** 다른 기기에서 열면, **Then** 일기·음성 각각의 준비 상태를 알리고 재시도를 제공한다.
4. **Given** 연결되지 않은 기기 또는 다른 가족 보관함,
   **When** 기록에 접근하면, **Then** 일기·원본 음성을 열거나 듣지 못한다.
5. **Given** 차량에서 이전 기록을 읽거나 듣고 있는 상황,
   **When** 주행으로 전환되거나 상태가 불명이 되면,
   **Then** 허용된 주행 상태이면 읽기를 잠그고 원본 청취만 유지한다. 상태불명/음성 허용 상실이면 재생도 중단하고 자동 재개하지 않는다.
6. **Given** 보호자가 차량 연결을 해제한 상황,
   **When** 차량이 온라인 확인을 마치면,
   **Then** 보관함 접근을 종료하고 해당 차량의 보관함 사본을 지운다.
   오프라인 해제는 확인 대기 상태로 표시한다.

### User Story 3 - 중단·재접속·삭제에도 기록을 관리한다 (Priority: P1)

출발이나 연결 오류로 기록이 중단돼도 부모가 완료된 내용을 다시 이어 보고,
원하지 않는 기억은 일기와 음성을 함께 삭제한다.

**Why this priority**: 실제 가족 음성을 보관하고 여러 기기에서 다루므로 데이터 관리도 첫 버전의 일부다.

**Independent Test**: 임시 저장·동기화 대기·저장 완료 기록을 준비해
중단·재시도·재접속·삭제를 수행한다. 새 음성 수집 없이 복구 동작을 검증한다.

**Acceptance Scenarios**:

1. **Given** 가족이 이야기하는 중,
   **When** 차량 상태 또는 플랫폼 음성 허용이 불명이 되면,
   **Then** 녹음을 중단하고 완료된 발화·재생 가능한 원본을 보존하며 미완료 부분은 구분한다.
2. **Given** 전송 실패로 차량에만 남은 기록,
   **When** 연결 복구 후 재시도하면,
   **Then** 같은 기록이 중복되지 않고 음성과 일기가 같은 발화에 연결된다.
3. **Given** 생성 실패·앱 재시작,
   **When** 보관함을 다시 열면,
   **Then** 확인 완료한 발화·원본 음성을 복구해 재생성할 수 있고 이전 저장본을 덮어쓰지 않는다.
4. **Given** 저장한 기억,
   **When** 보호자가 삭제를 확인하면,
   **Then** 일기·원본 음성과 관련 사본을 함께 삭제하고 아직 오프라인인 기기의 삭제는 대기로 표시한다.
5. **Given** 삭제 전에 오프라인이 된 기기,
   **When** 다시 연결되면,
   **Then** 먼저 삭제 상태를 적용하고 이전 사본을 재업로드해 되살리지 않는다.

### Edge Cases

- 한 발화에 두 사람이 동시에 말함: 사용자가 발화자·인식문을 확인하거나 다시 녹음한다.
  자동 분리·자동 신원 추정을 약속하지 않는다.
- 구성원 변경 후 늦은 인식 결과가 도착함: 이전 발화에만 연결하고 다음 사람의 기억에 넣지 않는다.
- 아무도 말하지 않음: 빈 상태를 안내하고 일기·감정을 생성하지 않는다.
- 사실·장소가 서로 충돌함: 명시적으로 같은 사실을 정정한 경우에는 정정을 반영한다.
  명시적 정정 없이 다른 사람의 주장과 충돌하면 검토 대상으로 두고 한쪽을 확정하지 않는다.
- 오늘·어제·다음 여행 계획이 섞임: 시점을 구분하고 계획을 이미 일어난 사건으로 쓰지 않는다.
- 여러 장소가 한 녹음에 섞임: 내용을 사건별로 분류하고 한 장소로 강제 배정하지 않는다.
- 긴 입력이 내부 처리상 나뉨: 같은 세션·화자·정정 맥락을 유지하고 주제별 재녹음을 요구하지 않는다.
- 요약에서 내용이 빠짐: 제외한 내용과 원본에 접근할 수 있고 사용자가 다시 포함할 수 있다.
- 발화 내용에 생성 방식을 바꾸라는 문장이 있음: 기억 자료로 다루며 제품의 생성 규칙을 바꾸지 않는다.
- 음성 저장 공간 부족·권한 없음: 녹음 시작 또는 보관 실패를 안내하고 완료로 표시하지 않는다.
- 원본 음성은 남았지만 인식 실패: 같은 녹음으로 재시도하거나 문장을 직접 확인한다.
- 일기는 저장됐지만 음성 전송 실패: 전체 동기화 완료로 표시하지 않는다.
- 지하 주차장·통신 불가: 확인된 발화와 원본을 해당 기기에 임시 보관하며 전송 상태를 구분한다.
- 온라인에서 해제한 차량이 오프라인임: 즉시 원격 삭제됐다고 표시하지 않는다.
- 원본 음성은 외부에서 촬영·복제될 수 있음: 제품이 관리하는 사본의 삭제 범위를 안내한다.

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 확인된 플랫폼 허용 범위에서 주행 중 녹음·원본 재생을 제공한다. 읽기·편집·사진·검토는 주차 확인 시에만 허용한다.
  상태불명·플랫폼 허용 또는 포커스 상실 시 미디어를 중단하고 자동 재개하지 않는다. 허용된 P→주행 전환에서는 녹음/재생을 유지하며 시각적 검토만 잠근다. (C019, US1, US2-5, US3-1)
- **FR-002**: 보호자가 공동 기록임을 확인한 뒤 녹음을 시작할 수 있어야 하며,
  구성원 선택·건너뛰기를 제공하고 선택하지 않은 사람을 목소리로 추정하지 않아야 한다. (US1-1, US1-5)
- **FR-003**: 세션·발화별 실제 원본 녹음·원래 인식문·확인된 수정문·발화자와
  기억의 근거 음성 구간을 연결해 보관해야 한다.
  원본 확보 실패는 별도 미완료 상태로 알려야 한다. (US1-1, US1-3, US1-6)
- **FR-004**: 사용자는 사전 장소 입력 없이 녹음하고 정리된 사건별 장소를 확인·변경·미정 처리할 수 있어야 하며,
  현재 위치만으로 이야기 속 방문 장소를 확정하지 않아야 한다. (US1-4)
  발화에 명시한 일반 장소명도 보존하며 고유 지명·상호가 없다는 이유만으로 장소를 비우지 않는다.
- **FR-005**: 기록된 발화로 사람별 기억과 공동 일기 초안을 만들고 최종 저장 전에 묶음 검토를 제공해야 하며,
  각 생성 문장에서 근거 발화를 확인할 수 있어야 한다. 발화에 없는 사건·감정·참여자를 추가하거나
  다른 사람의 감정을 옮기지 않아야 한다. (US1-1, US1-2)
- **FR-006**: 사용자는 녹음 종료 후 인식문과 일기 초안을 묶음 검토·수정·저장할 수 있어야 하며,
  문장 수정이 실제 녹음을 변경하지 않아야 한다. (US1-3)
  확인 질문과 사건별 확인 필요 표시를 일치시킨다. 선택 정보가 없는 것만으로 확인을 요구하지 않는다.
- **FR-007**: 보호자가 관리하는 한 가족 보관함에 차량과 휴대폰을 연결하고 해제할 수 있어야 한다.
  연결되지 않은 기기·다른 보관함의 접근을 막고, 해제 완료 시 차량의 해당 사본을 제거해야 한다. (US2-1, US2-4, US2-6)
- **FR-008**: 일기·원본 음성·발화 연결을 양쪽 기기에 제공하고,
  해당 기기 저장·전송 대기·전송 오류·다른 기기 사용 가능 상태를 구분해야 한다. (US2-2, US2-3, US3-2)
- **FR-009**: 차량과 휴대폰 모두에서 기록 연월별 목록·기간 선택·날짜/장소/제목 검색으로 기록을 찾고,
  일기를 읽으며 전체 녹음과 원문 구간을 함께 보고 재생·일시정지·탐색·종료할 수 있어야 한다.
  구간 선택 시 해당 시점부터 전체 끝까지 이어 재생하며 현재 구간을 표시한다. (US2-2)
- **FR-010**: 생성·전송 실패·재시작 후 확인된 입력과 원본을 복구하고,
  재시도가 기록을 중복시키거나 다른 발화에 음성을 붙이지 않아야 한다. (US3-2, US3-3)
- **FR-011**: 보호자가 차량 또는 휴대폰에서 기록 삭제를 확인하면 일기·음성을 함께 삭제해야 한다.
  미연결 기기는 대기로 표시하고 재연결 시 삭제를 먼저 반영해 기록이 되살아나지 않아야 한다. (US3-4, US3-5)
- **FR-012**: 목소리를 가족 보관함에 보관하고 연결 기기에서 읽고 듣는다는 점,
  전송 여부·기기 해제·삭제 범위를 이해할 수 있게 안내해야 한다. (US1-1, US2-6, US3-4)

- **FR-013**: 여러 사건·장소·시점·주제가 섞인 입력을 받아 자동 분류·정제해야 한다.
  한마디·특정 짧은 길이·장소별 사전 분류·발화별 확인을 기록 절차로 강제하지 않아야 한다.
  불명확한 분류·순서는 미정으로 표시해야 한다. (US1-1, US1-7)
- **FR-014**: 같은 사건의 의미 중복·군더더기를 정리하고 명시적 정정을 반영해야 한다.
  서로 다른 사람의 감정은 합치지 않아야 하며, 정정이 아닌 충돌은 검토 대상으로 남겨야 한다.
  다른 날짜·미래 계획을 오늘의 실제 사건으로 바꾸지 않아야 한다. (US1-2, US1-7~9)
- **FR-015**: 정리 결과의 사건 묶음·장소·시점·포함 여부를 사용자가 수정할 수 있어야 한다.
  정리에서 제외한 말도 원본에 보존하고 재포함할 수 있어야 하며,
  분리·병합 후에도 발화자·근거 구간 연결을 유지해야 한다. (US1-9~10, US2-2)

### Key Entities *(include if feature involves data)*

- **가족 보관함**: 보호자가 관리하는 기록 묶음. 연결된 차량·휴대폰과 접근 관계를 가진다.
- **구성원**: 세션에서 사용자가 선택한 이름·별칭. 개별 비공개 계정이나 음성 신원이 아니다.
- **이야기 세션**: 녹음 시작부터 종료까지 이어지는 입력 묶음. 여러 사건·시점·장소·발화를 포함한다.
- **사건 묶음**: 세션의 발화를 분류한 결과. 장소·시점·주제·검토 상태를 가지며 분리·병합할 수 있다.
- **여행·방문**: 사건들을 연결하는 맥락. 입력 전에 한 방문을 반드시 선택하는 구조가 아니다.
- **발화**: 선택한 구성원, 실제 원본 음성, 인식문, 확인문, 완료·실패 상태를 가진다.
- **일기**: 사건별·개인별 기억과 공동 문장, 근거 발화·음성 구간, 사용자 수정·저장 버전을 가진다.
- **기기 연결·동기화 상태**: 어느 보관함에 연결됐고 어느 기록의 일기·음성이 준비됐는지 나타낸다.
- **삭제 상태**: 삭제 결정과 각 기기의 반영 상태를 추적해 이전 사본의 복원을 막는다.

## 차량 맥락 확장 — 2026-11-08

- **FR-016**: 차 별명·제조사·모델·차종·연식·선택적 차 번호를 기록 당시 차량 스냅샷으로 보존하고 양쪽 기기에서 일기와 함께 볼 수 있어야 한다. 프로필 수정/차 교체는 기존 기록을 변경하지 않는다. 예전 차 기록은 유지하며 기록의 차량 ID로 모아볼 수 있어야 한다. 활성 연결 차량 1대 제약과 과거 차 보존은 양립한다.
- **FR-017**: **녹음 시작 시점의 차량 위치**를 기록해야 한다. 관측 시각·출처·지원/권한/품질 상태를 보존하고 오래되거나 없는 위치는 미확인으로 표시한다. 생성·편집·휴대폰 열람 시각의 위치로 대체하지 않는다. 위치 없는 기록도 허용한다. ‘녹음을 시작한 곳’은 발화 속 방문지와 별도 필드이며 사건 발생 장소를 추정하는 근거로 강제하지 않는다.

추가 수용 기준: 차량 프로필 변경 후 이전 일기의 차량 정보가 그대로 남는다. 다른 차량의 과거 기록도 차량별 조회가 가능하다. 현재 위치를 얻지 못했을 때 오래된 마지막 위치를 현재 녹음 위치로 표시하지 않는다. 번호/위치는 가족 보관함 권한·삭제에 포함하며 일기 생성 LLM 입력에 번호·VIN·정밀 좌표를 새로 보내지 않는다.

## 사진·재방문 확장 — 2026-11-08

- **FR-018**: 보호자가 휴대폰/웹에서 일기에 사진 여러 장을 직접 첨부하고, 차량과 휴대폰에서 확대 열람·개별 삭제할 수 있어야 한다. 차량에서는 파일 선택·첨부를 요구하지 않는다. 파일 형식·용량·장수 제한과 저장 실패/재시도를 표시하며 저장 완료 전 완료로 알리지 않는다. 사진은 해당 가족/일기와 연결하고 기기별 전송 상태를 구분한다. 일기 삭제 시 사진도 삭제한다. 사진 자동 수집·사진 기반 사실 생성은 제외한다.
- **FR-019**: 녹음 시작 위치 주변의 같은 가족 과거 기록을 추천하고 사용자가 당시 음성을 들을 수 있어야 한다. 현재 기록/동시각·미래 기록/다른 보관함/삭제 기록은 제외하고 차가 달라도 같은 가족의 과거 기록은 허용한다. 위치 없음·stale·좌표 없음은 미확인으로 안내한다. 차량은 주차 확인 후에만 사용하며 자동 재생/상시 위치 추적을 하지 않는다.

수용 기준: 사진 첨부 후 동일 브라우저 재열람, 다른 일기에 사진 미노출, 삭제 후 재열람에서도 삭제 유지, 잘못된 파일/용량 초과/저장 실패 시 기존 사진 유지. 재방문은 근접 좌표와 날짜를 검사하고 동일 이름만으로 결과를 만들지 않는다. 과거 기록의 목소리 열기 후에는 사용자가 재생 버튼을 누른다.

## Success Criteria *(mandatory)*

### Measurable Outcomes

모든 수치는 목표이며 구현·실험 결과가 아니다. 사용성 표본은 초기 탐색이며 시장 수요의 증거로 확대하지 않는다.

- **SC-001**: 최초 기기 연결을 마친 5가족 중 4가족 이상이 여러 사건을 사전 분류 없이
  자유롭게 말하고, 종료 후 검토·저장에 쓰는 능동 조작 시간이 2분 이내다.
  발화 시간·생성 대기·최초 설정 시간은 별도 보고하며 전체 경험 지연을 숨기지 않는다.
- **SC-002**: 상반된 감정·무응답·사실 충돌·명령형 발화를 포함한 준비된 검증 사례에서
  근거 없는 사건·참여자·감정 전이와 잘못 연결된 원본 음성이 0건이다.
- **SC-003**: 준비된 동일 기록을 차량과 휴대폰에서 각각 찾는 과제에서,
  5가족 중 4가족 이상이 각 기기에서 30초 안에 목표 발화의 재생을 시작한다.
- **SC-004**: 정의된 중단·재시도·앱 재시작 사례 모두에서 완료된 발화와 재생 가능한 원본이 보존되고,
  재접속 후 일기·음성 불일치·중복 기록·삭제 기록 부활이 0건이다.
- **SC-005**: 다른 보관함·연결되지 않은 기기·온라인 해제 완료 기기의 접근 시나리오 모두에서
  원문과 음성을 열람·재생할 수 없다.
- **SC-006**: 허용된 주행 전환에서는 음성 기능을 유지하고 열람/편집을 잠근다. 상태불명·플랫폼 허용 또는 포커스 상실 때는 녹음/재생이 중단되고 복구 후 자동 재개되지 않는다.

- **SC-007**: 여러 장소·시점·반복·정정·충돌·계획·잡담을 섞은 검증 사례에서
  명시적 정정과 시점 구분을 모두 반영하고, 없는 장소명·순서·사건을 추가하지 않는다.
  기대 핵심 사실은 정리 결과에 반영되거나 검토 대상으로 표시돼야 한다.
  제외한 말의 재포함과 분리·병합 후 원본 구간 접근이 모든 준비 사례에서 가능하다.

## Assumptions

- **사용자 결정:** 가족 여행 기록, 자유 발화의 자동 분류·정제, 원본 녹음 보관, 차량·휴대폰 양쪽 읽기·듣기는 첫 버전 필수다.
- **초기 타깃 가설:** 초등학생 자녀와 자동차 나들이를 하고, 사진은 남기지만 정리를 미루는 부모.
  수요·지불 의사·재사용은 아직 검증되지 않았다.
- **작업 기준:** 한 보관함·차량 1대·보호자 휴대폰 1대. 보호자가 연결과 삭제를 관리하고
  자녀는 별도 계정 없이 자발적으로 참여한다. 가족별 카드는 비공개 개인 일기가 아니다.
- **기록 단위:** 여러 사건을 담는 이야기 세션이며 1명 이상 참여할 수 있다.
  사용자는 생각나는 대로 말하고 시스템이 정리한다. 주제 변경마다 발화를 끊지 않는다.
  녹음의 기술적 길이·용량 한도는 검증 후 안내하며 무제한을 약속하지 않는다.
  발화자 수동 선택은 유지하고 자동 신원 식별·동시 발화 분리는 별도 후속 범위다.
- **첫 버전 제외:** 자동 화자 분리·신원 식별, 상시 녹음, 사진 자동 수집·영상, 지도 경로,
  인쇄 책, 공개 링크, 다중 보호자 계정, 휴대폰 신규 음성 작성, 운전 중 차량 사용.
- **네트워크:** 기기 간 최초 전송에는 통신이 필요하다. 미전송·미다운로드 음성은
  다른 기기에서 즉시 오프라인 재생 가능하다고 표시하지 않는다.
- **보관:** 첫 버전은 사용자가 삭제할 때까지 관리되는 보관함을 목표로 한다.
  무제한 용량·평생 서비스·외부 복제본 삭제를 약속하지 않는다.
  실제 보관 서비스의 운영·백업·삭제 정책은 plan에서 정하고 수집 전에 안내한다.
- **의존성:** 해당 차량에서 원본 음성을 확보하고 주차를 판정할 수 있어야 한다.
  미확인 부분과 실제 검증 기준은 [기술 근거](../../docs/technical-evidence.md)에 기록한다.
- **정본:** 제품 목적·타깃은 [제품 정의](../../docs/product-brief.md), 변경 근거는
  [결정 이력](../../docs/decisions.md)을 따른다.

## 연결 별칭·차량 기본값·사진 구도 — 2026-11-09

- FR-007 보강: 연결 시 기기 별칭(공백 제거 후 1~40자)을 정하고 차량/보호자 웹에서 수정한다. 서버 성공 후 완료 표시, 같은 보관함·기기 본인 권한만 허용한다. 차량 프로필 별명과 연결 기기 별칭은 별도이며 과거 기록을 수정하지 않는다. 활성 차량 1대 제약은 유지한다.
- FR-016 보강: 설정 진입 시 지원되는 차량 제조사/모델/연식을 조회해 빈 필드의 기본값으로 제안한다. 저장 전 자유롭게 수정·확정한다. 사용자 입력/저장값을 비동기 응답으로 덮어쓰지 않는다. 미지원/권한 거절/시간 초과 시 수동 입력을 유지한다. 에뮬레이터 응답은 실차 정보와 구분한다. VIN을 조회하지 않고, 차종·번호는 검증된 조회 경로가 없으면 직접 입력한다.

## C022 — 보고서에서 확정한 목표 경험 (아직 미구현)

차량은 밝은 환경에서 라이트, 야간·터널 등 어두운 환경에서 다크를 제공한다. 실제 테마/조도 신호 지원을 확인하고 수동 선택을 제공한다. 현재 다크 고정은 구현 상태일 뿐 최종 요구사항이 아니다.

주행 중 플랫폼이 허용하는 최소 조작으로 TTS 시작/이전/다음을 제공하고 사용자가 선택·시작한 일기 목록에서 정상 완료 후 다음 항목으로 이어 듣는다. UNKNOWN·포커스 상실·사용자 중단 시 다음 항목을 자동 시작하거나 복구 후 자동 재개하지 않는다. 복잡한 선택/검토는 주차 후 제공한다. 현재의 원본 이전/다음과 TTS 큐를 혼동하지 않는다.

최초 공유 정책은 C023의 완성 일기 자동 동기화로 대체한다. 라이트/다크는 모바일 웹에서도 시스템 테마 연동과 수동 선택을 제공한다.

## C023 — 완성 일기의 자동 동기화

사용자 요청으로 C015~C022의 ‘최초 일기별 공유 버튼 필요’를 대체한다. 같은 가족 보관함에 연결한 뒤에는 일기를 최종 저장하는 동작만으로 일기·원본·기록 당시 맥락을 자동 동기화한다. 인식문 수정 중·검토 전 초안은 자동 게시하지 않는다. 다시 수정한 일기도 최종 저장한 revision만 반영한다.

- 최초 연결 시 기록이 가족 보관함에 저장되는 범위를 안내한다. 최초 연결 전 이 기기에서 완성한 미연결 기록도 포함한다. 다른 보관함에 연결됐던 기록은 재연결로 다른 가족에게 자동 전송하지 않는다.
- 최종 저장과 영속 outbox 등록을 복구 가능한 하나의 로컬 작업으로 취급한다. 서버 응답 전에도 로컬 기록을 보존하며, 앱 종료·재시작 뒤 작업을 복구한다.
- 네트워크 복구·앱 실행/복귀·최종 저장이 작업 실행 계기다. 플랫폼이 허용하는 예약 백그라운드 작업을 이용하되 앱 강제 종료·차량 전원 종료에서도 즉시 동기화된다고 보장하지 않는다. 실패한 작업만 지수 backoff로 재시도하고 서버 변경 데이터 폴링은 추가하지 않는다.
- 변경 수신은 기존 SSE+cursor를 유지한다. 차량에서 파일/화면에 적용하는 시점은 P+UX 제한 없음+녹음/STT/청취/편집 중이 아닌 상태다. 신호 대기나 임시 정차를 주차로 간주하지 않는다.
- 사진 추가·삭제·일기 삭제를 같은 보관함에 반영한다. 삭제가 대기 중 업로드보다 우선하며, 실패/재실행으로 삭제한 일기를 되살리지 않는다.
- 기본 표시를 ‘동기화 대기/동기화 중/동기화 완료’로 정리한다. 미연결은 ‘기기에 저장됨·연결 필요’, 작성 중은 ‘작성 중’으로 별도 표시한다. 실패 때 재시도/재연결 이유를 제공한다. 완료는 해당 기기와 서버의 일치이며 모든 오프라인 기기의 반영을 뜻하지 않는다.

수용 기준: 연결된 상태에서 최종 저장만 하면 휴대폰에서 같은 일기/원본을 조회한다. 오프라인 완료→온라인 복구와 전송 중 앱 재시작에서 중복 없이 복구한다. 초안은 서버에 게시되지 않는다. 사진 수신은 편집·재생을 방해하지 않는다. 다른 보관함 재연결·인증 만료·삭제 경합에서 오게시/부활이 없다. 자동 공유 정책은 원본 캡처·서버 보관의 플랫폼 지원 범위 확인을 대신하지 않는다.

## C023 기능 설명 검토

전체 원본 재생/현재 재생 위치/파형은 구현됐다. 정확한 발언별 타임라인은 아직 구현·검증되지 않았으며 STT 구간과 원본 시각 정렬을 검증해 제공한다. 자동 화자 식별이나 LLM 추정 시각으로 대신하지 않는다. 날짜별 목록과 차량 필터는 양쪽에 있으며, C024에서 차량·모바일 검색 진입점을 검색·필터 패널로 통합했다. 주행 거리·시간·목적지는 후속 확장이며 녹음 시작 위치와 일기의 실제 사건 장소는 구분한다.


## C024 — 검색·필터 통합과 양쪽 화면 테마

- 모바일/차량 일기 목록의 상시 ‘기록한 차량’ 선택 행과 별도 검색 진입점을 하나의 ‘검색·필터’로 통합한다. 한 패널에서 검색어와 기록 당시 차량 조건을 조합하고 적용/초기화한다. 결과에는 적용 중임을 간결히 알리고 조건은 목록 재진입 때 유지한다.
- 모바일 목록의 ‘우리 가족 차 안의 이야기’ 제목을 제거하고 차곡·연결 상태·검색 진입점 중심으로 정리한다. 큰 소개 문구나 중복 탭을 추가하지 않는다.
- 차량과 모바일 웹에서 자동(기기 설정 따름)/라이트/다크를 제공하고 기기별 선택을 유지한다. 사진·원본·일기 데이터는 색상 모드와 무관하다.
- 차량 자동 모드는 Android Configuration의 주야간 신호(uiMode)를 따른다. 신호 미확인 시 마지막 알려진 상태, 없으면 다크를 사용한다. 실제 터널 감지는 차량 플랫폼이 신호를 전달해야 하며 시간·GPS로 터널을 추정하지 않는다. 모바일 자동 모드는 prefers-color-scheme을 따른다.
- 테마 변경은 DOM/Activity를 재생성하거나 미디어를 중단하지 않는다. 녹음 시간, 청취 위치, 편집 중 문장, 스크롤/선택 상태가 유지된다. 주행 중 수동 설정·검색은 기존 검토 제한을 따른다.
- 주요 본문/보조 글/포커스/입력/대화상자/사진 뷰어/오류 상태까지 토큰을 적용하고 사진 색상을 반전하지 않는다.

수용 기준: 양쪽 목록에서 하나의 메뉴로 검색어+차량 조건/초기화가 작동한다. 모바일 제목/상시 차량 선택 행이 사라진다. 두 테마와 자동 변경·수동 우선·재실행 유지, 자동 전환 중 원문 입력/재생 보존을 검증한다. 실차 터널 신호와 iPhone Safari 실기기 확인은 에뮬레이터/브라우저 모의 검증과 구분한다.


## C025 / C022c 차량 TTS 플레이리스트

- 차량 검색 결과 전체의 완성 일기만 최신순(동일 시각은 ID 순)으로 재생한다. 월 이동과 무관하게 적용 중 검색·차량 조건의 전체 결과이며 버튼에 개수를 표시한다. 초안/수정 미확정/빈 일기는 제외한다. 시작 시 파일·제목·확정 본문을 고정하고 외부 변경을 끼워 넣지 않는다.
- 목록의 이어 듣기는 첫 항목부터, 상세 읽기는 해당 한 편만 재생한다. 주행 화면의 일기 듣기는 선택한 완성 일기부터 최신순 목록을 시작하며 선택이 부적합하면 첫 완성 일기부터 시작한다. 재생 중에는 이전/다음/종료를 제공한다. 경계에서는 이동을 비활성화하며 반복하지 않는다.
- 정상 onDone만 다음 일기를 시작한다. SDK stop/error/timeout, 오디오 포커스 loss/duck(TTS 음량 제어 미지원), UNKNOWN, 동의 철회, 종료/프로세스 종료는 큐를 비우고 재생 권한을 끝낸다. 오래된 콜백으로 다음 항목을 재생하지 않는다. 복구 후에는 사용자 시작이 다시 필요하다.
- 재생 큐는 PlaybackService에 두며 화면 이탈/내비게이션 전환/Activity 재생성에 유지한다. MediaSession·알림에서도 이전/다음/종료를 지원한다. 본문을 알림에 표시하지 않는다. 주행 화면은 순번/전체 개수와 최소 조작만 표시한다.
- TTS는 원본 위치/파형과 별개다. TTS 시 원본 진행을 표시하지 않는다. SDK에 정확한 pause/resume 시점 기능을 가정하지 않고 종료와 명시적 재시작을 제공한다. 기존 원본 일시정지 기능은 유지한다. 모바일 웹 TTS·실차 DO 허용·모델 품질은 이번 완료 범위가 아니다.

검증: 실제 SDK 연속 onDone, 이전/다음·끝·정지 경합·오래된 콜백·엔진 오류·UNKNOWN/포커스 무재개, 내비게이션 중 연속, 재접속 상태, 완성본 검증/정렬/필터/빈 목록·두 테마 UI.


## C026 / C023f 원본 발언 타임라인

- 실제 PCM과 STT EPD 기준을 합성 다중 발언 입력으로 검증한다. 콜백 수신 시간·문장 길이·LLM 추정 시각을 사용하지 않는다. 확정 텍스트와 1:1로 대응되고 유효한 범위만 탐색 가능하게 한다. 불일치/범위 역전/누락은 원본과 텍스트를 보존하고 시각은 비워 둔다.
- 원본에 결속된 `speech_timeline.segments`는 원문/시작·종료ms/근거 종류를 저장한다. 수정된 확인문으로 원문 구간을 덮어쓰지 않는다. 재인식은 새 raw_history와 연결된 결과로 명시적으로 교체한다. 이전 레코드는 필드 없음으로 읽고 전체 원본·기존 확인문을 제공한다.
- 양쪽 원본 듣기에 시간과 원문 목록을 제공한다. 클릭 시 해당 원본 선택→탐색→재생, 재생 중 현재 구간 강조, 무음 공백에는 강조 없음. 타임라인 탐색은 차량의 주차 검토 권한을 유지한다.
- 서버는 길이·정수·순서·겹침·원본 길이·원문 결속을 검증하고 unknown 필드를 제거한다. 동기화 이후에도 같은 구간/원문과 원본 SHA를 보존한다. 일기 생성은 현재의 확인문 전체 입력·목업 계약을 유지한다.
- 화자는 SDK 근거 없이 자동 지정하지 않는다. 실제 가족의 이름과 익명 화자 A/B 구분, 겹친 음성 분리의 차이를 연구 결과에 명시한다. 추가 모델 설치·외부 음성 전송은 하지 않는다.


## C027 화면 일관성 보정
- 차량 설정→녹음/일기 및 뒤로 가기에서 네이티브 설정 화면과 faithful 표시/route 상태를 일치시킨다. 녹음 탭 이동만으로 녹음을 시작하지 않는다.
- 태양/달 SVG 버튼은 설정 탭 진입 없이 즉시 밝기 테마를 전환하며 접근성 이름으로 전환 대상을 알린다. 차량 탐색 영역/모바일 홈에서 자동 모드 복귀도 바로 제공한다. 모바일 상세/원문/연결에도 바로 전환 버튼을 제공한다.
- 테마는 기존 기기별 저장/시스템 자동 정책과 주차 검토 권한을 유지한다. 화면 전체 재생성이나 미디어 중단 없이 색상과 버튼 상태만 갱신한다.
- 녹음 시간/파형은 의미 있는 DOM 식별자에 연결한다. CSS 선언 공백/색상 변경에 의존하지 않는다. 양쪽 테마·일시정지/재개·감소된 움직임 설정에서도 실입력 변화를 표시한다.

## C028 테마 피드백·검색 정규화·실제 음성 종료·패널 정리
- 자동 테마는 차량 OS/휴대폰의 화면 설정을 따른다는 기준과 현재 라이트/다크 적용 결과를 표시한다. 수동 선택을 자동으로 오해하지 않도록 구별한다.
- 정보가 없는 과거 차량 snapshot과 빈 필드 snapshot은 하나의 `차량 정보 없음` 필터로 합친다. 실제 식별 정보가 있는 차량은 유지하며 저장된 snapshot을 수정하지 않는다.
- 듣기 종료는 큐 상태뿐 아니라 공식 SDK 음성 출력을 중단해야 한다. 비동기 stop 처리 전에 엔진 연결을 해제하지 않으며 종료 중 재시작/늦은 콜백으로 음성이 겹치지 않는다.
- 모바일 검색·필터/가족 패널의 하단 닫기는 우측 상단 X로 대체하고 접근성 이름·44px 이상 터치 영역·키보드 닫기/포커스 복귀를 유지한다. 가족 패널의 화면 설정은 제거한다.
- MediaSession의 이전/다음/종료와 물리 입력의 연결을 조사·검증하며, 일반 Android 지원과 Pleos 실차 장치 지원을 구분한다. 로터리/터치패드 실차 지원을 검증 없이 주장하지 않는다.

## C029 검색 명칭·모바일 수동 테마·차량 설정 재설계
- 검색 진입 버튼/패널 제목/접근성 이름은 `검색`으로 통일한다. 차량 필터와 초기화 기능은 같은 패널에 유지한다.
- 모바일 웹은 태양/달 수동 전환만 제공하고 OS 변화에 자동 전환하지 않는다. 기존 auto/미설정은 라이트로 이행한다. 차량 auto/light/dark 정책은 유지한다.
- Downloads의 차량앱 설정화면 PNG를 시각 기준으로 왼쪽 112px 탐색, 2열 카드, 어두운 배경, 큰 버튼/간격을 구현하고 라이트 토큰에도 대응한다.
- 설정의 첫 화면은 휴대폰 연결/우리 차/녹음 위치/화면 모드 4개 카드다. 코드 연결·연결 별칭·수동 재시도, 차량 정보 조회/수정/저장, 위치 권한 안내/요청, 차량 테마는 실제 기능에 연결한다. 세부 입력은 별도 패널로 연다.
- 자동 녹음과 주행 안전 해제는 추가하지 않는다. 샘플 위치·모의 P 해제·목업/SDK 상태 설명은 사용자 설정에서 노출하지 않는다. 미구현 토글을 작동하는 것처럼 표시하지 않는다.
- 기존 차량 snapshot/계정 연결/기록 보존, 주차 및 유휴 권한, 입력 오류·동기화 실패 피드백과 설정↔녹음/일기 이동을 검증한다.

## C030 차량 공통 탐색과 단일 테마 전환
- 녹음·일기·설정 및 하위 차량 화면에 동일한 왼쪽 탐색 DOM/아이콘/간격을 사용한다. 선택 탭만 달라진다.
- 차량 테마 조작은 하나의 버튼으로 자동→라이트→다크→자동을 순환한다. 버튼에는 현재 모드, 접근성 이름에는 현재/다음 모드를 표시한다. 자동 적용 색상·시스템 기준은 안내로 알린다.
- 설정의 화면 모드 카드를 제거하고 연결·우리 차·녹음 위치만 남긴다. 모바일은 기존 수동 라이트/다크 버튼을 유지한다.
- 기존 저장값·시스템 자동 처리·녹음 입력·재생·주차 권한을 유지한다. 테마만 바꿀 때 화면이나 미디어를 재생성하지 않는다.

## C031 차 별명 단일화
- 연결 별칭과 차 별명을 하나로 통합한다. 차량에서는 우리 차 정보에서만 수정하고 연결 패널에는 이름 입력란을 두지 않는다. 휴대폰 차량 관리도 `차 별명`으로 표시한다.
- 처음 설정을 열 때 기존 차량 별명을 우선 이행한다. 비어 있으면 연결 이름/모델/우리 차 순으로 채운다. 새 이름은1~40자로 통일한다. 기존40자 초과 이름은 자르지 않고 수정을 요청한다.
- 차량의 이름 변경은 로컬에 보존하고 연결 목록으로 전송한다. 오프라인 변경은 재시도하며 실패/대기를 표시한다. 휴대폰에서 변경한 이름은 SSE 및 변경 수신 시 현재 차량 정보에도 적용한다.
- 과거 일기 context.vehicle.nickname은 불변이다. 이름 변경 이후 시작한 녹음부터 새 이름을 복사한다. 연결 해제/재시작 시에도 마지막으로 확인한 차 별명을 보존한다.

## C032 주행 화면 회귀 복구
- 에뮬레이터에서 P+동의 또는 동의+주행으로 진입한 양쪽 경로 모두 시험 모드 전환 버튼을 제공한다. 실제 차량의 모의 상태 제어를 허용하는 근거로 쓰지 않는다.
- Downloads의 차량 녹음 PNG와 동일한 왼쪽 바·타이머·파형·녹음 제어 배치를 주행 화면에 적용한다. 인식문 대신 주차 후 확인 안내와 기존 음성 청취 제어를 제공한다. 긴 본문/사진/설정 편집은 계속 차단한다.
- 녹음 없이 주행→주차 전환 시 carhome으로 이동한다. 실제 새 녹음 완료로 검토가 대기 중이면 해당 기록의 확인 화면으로, 녹음 중이면 녹음 화면으로 복귀한다. 과거 청취용 자동 선택 기록은 검토 대기로 취급하지 않는다.

## C033 고정 목업 일기
- 새 목업 생성 결과의 본문은 정확히 `AI 생성 일기 목업 입니다.` 한 문장이다. 입력이 여러 발언이어도 중복 출력하지 않는다.
- generation_mode=mock, 현재 session/revision과 원본 구간 연결을 유지한다. 실제 AI 요약/가족의 발언이라고 주장하지 않는다. 기존 저장 일기·인식문·원본은 일괄 수정하지 않는다.

## C034 Windows 팀 테스트와 제출 준비
- Windows Docker Desktop Linux 컨테이너에서 DB/web/worker/proxy/개발메일/목업서버를 실행한다. 에뮬레이터와 APK는 Windows 호스트에서 별도 실행한다.
- 개발자 .env·DB·녹음·사진·기기 토큰을 전달하지 않고 팀원별 비밀/볼륨을 새로 생성한다. 현재 개발 프로젝트와 팀 테스트 프로젝트는 분리한다.
- PowerShell에서 Node24 기반 초기화·실행·기기 연결·종료 명령을 제공한다. 첫 실행은 빌드가 필요하며 맥 ARM 이미지를 Windows x64 이미지로 간주하지 않는다.
- 공개 공지/FAQ/SDK 근거별 지원/금지/미확인을 구분하고 제출용 release APK 차이를 명시한다. 저장소 공개 변경·이메일 발송·공개 서버 생성은 하지 않는다.

## C035 독립 설치 가능한 심사용 release
- contestRelease는 debuggable=false인 별도 패키지 io.hmg.familydiary.contest이며 전용 서명 키로 서명한다. 기존 probeDebug 데이터와 충돌하지 않는다.
- 공식 에뮬레이터에서만 기존 음성·일기·동기화 기능을 제공한다. 모의 P/D 표시는 유지하고 실차 잠금·UNKNOWN 중단·주차 검토 제한은 완화하지 않는다.
- 일기 생성은 앱 내부에서 정확히 `AI 생성 일기 목업 입니다.`를 반환한다. 외부 API·개발자 PC·adb reverse 없이 녹음→검토→목업→저장→청취가 가능하다. session/revision/원본 참조 보존과 취소를 유지한다.
- release에서 run-as 없이 로컬 HTTPS 서버 설정 파일(주소·공개 CA만)을 사용자가 선택·확인해 가져온다. 주차/유휴 또는 초기 미연결 화면에서만 가능하다. 연결된 보관함의 서버를 다른 CA로 교체할 수 없다. CA가 같으면 IP 변경은 가능하다. 비밀·계정은 파일에 넣지 않는다.
- 키/환경/실제 기록을 제외한 소스·APK·실행 안내·검증 범위·커밋/해시를 제출 묶음으로 만든다. 미확인 플랫폼 허용·Windows 실기기 검증을 완료라고 쓰지 않는다.

C035 에뮬레이터 실측 보정: 현재 Pleos의 활성 사용자에서 ACTION_OPEN_DOCUMENT 처리기가 없다. 파일 선택 미지원 시 설정 JSON 붙여넣기를 제공하고, 팀 CLI가 공개 설정만 명시적 Intent로 전달하는 configure-release도 제공한다. Intent 수신만으로 저장하지 않으며 화면의 서버/CA 확인과 상태 재검증을 거쳐 적용한다.
