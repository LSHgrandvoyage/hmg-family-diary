# Feature Specification: 가족의 여행 기억과 원본 목소리 보관

**Feature Branch**: `main` (초기 명세 기준선; 기능 디렉터리와 Git 브랜치는 독립)

**Created**: 2026-11-08

**Status**: Draft — 제품·기능 기준선, 앱 구현 및 사용자 검증 전

**Input**: 가족 여행 음성 일기. 타깃·문제·베스트 시나리오부터 정의하고,
기록에 사용한 실제 녹음물을 보관해 차량과 휴대폰 양쪽에서 다시 읽고 듣는다.
한마디·짧은 발화·한 장소 형식에 제한하지 않으며 여러 이야기를 LLM이 분류·정제한다.

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 방문 후 가족의 기억을 남긴다 (Priority: P1)

초등학생 자녀와 나들이한 부모가 주차된 차에서 기록을 시작한다.
참여할 구성원을 선택해 자유롭게 말한다. 한 세션에 여러 사건·장소·시점이 섞여도
앱이 분류·정제한 일기를 묶음으로 검토하고 원본 녹음과 함께 저장한다.

**Why this priority**: 한 사람의 정리 부담을 줄이면서 여러 사람의 기억을 남기는 첫 가치다.

**Independent Test**: 두 사람이 식당·해변·어제의 카페 이야기를 순서 없이 말하고
중간에 사실을 정정한다. 사전 분류 없이 사건별 초안을 얻고 서로 다른 감정과
원본 구간 연결을 확인한다. 발화 길이는 검증 입력의 속성이며 사용자 형식 제약이 아니다.

**Acceptance Scenarios**:

1. **Given** 주차가 확인되고 공동 녹음 안내를 확인한 가족,
   **When** 아빠와 자녀가 각각 자신을 선택해 여러 이야기를 말하고 녹음을 마치면,
   **Then** 사전 분류·발화별 확인 없이 사건별 초안이 만들어지고 각 내용이 원래 발화자·녹음 구간에 연결된다.
2. **Given** 아빠는 파도를 좋아했고 자녀는 무서웠다고 말한 기록,
   **When** 일기를 만들면, **Then** 두 관점이 유지되고 ‘모두 즐거웠다’는 결론을 만들지 않는다.
3. **Given** 인식문에 잘못된 단어가 있는 기록,
   **When** 사용자가 문장을 수정하면, **Then** 생성은 수정문을 따르고 원본 녹음은 그대로 보존된다.
4. **Given** 현재 위치가 오래됐거나 이야기 속 방문지와 다른 상황,
   **When** 분류된 사건들의 장소 후보를 검토해 수정하거나 미정으로 두면,
   **Then** 각 사건의 확인된 장소만 저장본에 사용한다. 녹음 전에 장소를 입력할 필요는 없다.
5. **Given** 한 사람만 참여하거나 구성원이 건너뛴 상황,
   **When** 저장하면, **Then** 실제 참여자의 기억만 남고 나머지 사람의 기억을 만들지 않는다.
6. **Given** 녹음에 실패해 원본 음성이 확보되지 않은 발화,
   **When** 저장을 시도하면, **Then** 오류·재시도와 텍스트 임시 보관 상태를 표시하고
   원본까지 완성된 기억으로 표시하지 않는다.

7. **Given** 식당·해변·어제의 카페·잡담을 순서 없이 이야기한 세션,
   **When** 정리하면, **Then** 사건·시점별로 묶고 어제 이야기를 오늘 사건으로 바꾸지 않는다.
   불명확한 장소명·순서는 미정으로 두고 발화자 정보는 선택된 구성원을 따른다.
8. **Given** “점심 먹었어. 아, 아침이었지.”처럼 같은 사실을 명시적으로 정정한 발화,
   **When** 정리하면, **Then** 정정된 아침을 반영하고 원본의 두 표현은 그대로 들을 수 있다.
   명시적 정정이 없는 두 사람의 충돌은 임의로 덮어쓰지 않는다.
9. **Given** 같은 사건을 반복해 말하거나 관련 없는 메모가 섞인 입력,
   **When** 정리하면, **Then** 의미가 같은 반복은 통합하고 다른 관점은 유지한다.
   일기에 포함하지 않은 내용도 원문·원본에서 보며 다시 포함할 수 있다.
10. **Given** 사건별로 정리된 초안,
    **When** 사용자가 잘못 묶인 내용을 옮기거나 분리·합치기·포함 여부를 수정하면,
    **Then** 수정에 맞게 초안을 갱신하고 관련 원본 구간·발화자 연결은 유지한다.

### User Story 2 - 나중에 양쪽 기기에서 읽고 듣는다 (Priority: P1)

부모와 가족이 집에서는 휴대폰으로, 다음 나들이의 주차된 차에서는 차량 화면으로
이전 방문 일기를 찾아 읽고 해당 구성원이 당시 말한 실제 음성을 듣는다.

**Why this priority**: 다시 듣는 순간까지 완결해야 사용자가 선택한 첫 버전의 가치가 성립한다.

**Independent Test**: 음성과 일기가 준비된 보관함으로 시작해 차량과 휴대폰 각각에서
목표 날짜·장소의 기록을 찾고 같은 발화를 재생한다. 새 기록 작성 없이 검증한다.

**Acceptance Scenarios**:

1. **Given** 보호자가 관리하는 보관함과 연결 가능한 차량,
   **When** 보호자가 휴대폰에서 자신의 보관함과 차량의 연결을 확인하면,
   **Then** 해당 차량과 휴대폰은 같은 가족 기록에 접근한다.
2. **Given** 일기·음성이 동기화된 기록,
   **When** 기록 연월별 목록·기간 선택·검색으로 찾고 구성원의 재생을 누르면,
   **Then** 해당 기억의 근거 음성 구간부터 재생되고 전체 녹음도 들을 수 있다.
   전체 녹음 플레이어와 시간순 원문 구간을 함께 보여준다. 구간을 누르면 해당 시점으로 이동해
   재생하며 구간 끝에서 끊지 않고 전체 녹음 끝까지 이어진다. 현재 구간을 강조한다.
   재생·일시정지·탐색·종료할 수 있으며 떨어진 여러 근거 구간은 별도로 표시한다.
   보관함의 기본 묶음은 기록 연월이며 장소는 분류 탭 대신 메타데이터·검색 대상으로 둔다.
3. **Given** 음성이 아직 전송되지 않았거나 내려받기에 실패한 기록,
   **When** 다른 기기에서 열면, **Then** 일기·음성 각각의 준비 상태를 알리고 재시도를 제공한다.
4. **Given** 연결되지 않은 기기 또는 다른 가족 보관함,
   **When** 기록에 접근하면, **Then** 일기·원본 음성을 열거나 듣지 못한다.
5. **Given** 차량에서 이전 기록을 읽거나 듣고 있는 상황,
   **When** 주차 상태가 해제되거나 불명이 되면,
   **Then** 읽기 상호작용과 재생을 중단하고 자동 재개하지 않는다.
6. **Given** 보호자가 차량 연결을 해제한 상황,
   **When** 차량이 온라인 확인을 마치면,
   **Then** 보관함 접근을 종료하고 해당 차량의 보관함 사본을 지운다.
   오프라인 해제는 확인 대기 상태로 표시한다.

### User Story 3 - 중단·재접속·삭제에도 기록을 관리한다 (Priority: P1)

출발이나 연결 오류로 기록이 중단돼도 부모가 완료된 내용을 다시 이어 보고,
원하지 않는 기억은 일기와 음성을 함께 삭제한다.

**Why this priority**: 실제 가족 음성을 보관하고 여러 기기에서 다루므로 데이터 관리도 첫 버전의 일부다.

**Independent Test**: 임시 저장·동기화 대기·저장 완료 기록을 준비해
중단·재시도·재접속·삭제를 수행한다. 새 음성 수집 없이 복구 동작을 검증한다.

**Acceptance Scenarios**:

1. **Given** 가족이 이야기하는 중,
   **When** 출발·주차 상태 불명이 되면,
   **Then** 녹음을 중단하고 완료된 발화·재생 가능한 원본을 보존하며 미완료 부분은 구분한다.
2. **Given** 전송 실패로 차량에만 남은 기록,
   **When** 연결 복구 후 재시도하면,
   **Then** 같은 기록이 중복되지 않고 음성과 일기가 같은 발화에 연결된다.
3. **Given** 생성 실패·앱 재시작,
   **When** 보관함을 다시 열면,
   **Then** 확인 완료한 발화·원본 음성을 복구해 재생성할 수 있고 이전 저장본을 덮어쓰지 않는다.
4. **Given** 저장한 기억,
   **When** 보호자가 삭제를 확인하면,
   **Then** 일기·원본 음성과 관련 사본을 함께 삭제하고 아직 오프라인인 기기의 삭제는 대기로 표시한다.
5. **Given** 삭제 전에 오프라인이 된 기기,
   **When** 다시 연결되면,
   **Then** 먼저 삭제 상태를 적용하고 이전 사본을 재업로드해 되살리지 않는다.

### Edge Cases

- 한 발화에 두 사람이 동시에 말함: 사용자가 발화자·인식문을 확인하거나 다시 녹음한다.
  자동 분리·자동 신원 추정을 약속하지 않는다.
- 구성원 변경 후 늦은 인식 결과가 도착함: 이전 발화에만 연결하고 다음 사람의 기억에 넣지 않는다.
- 아무도 말하지 않음: 빈 상태를 안내하고 일기·감정을 생성하지 않는다.
- 사실·장소가 서로 충돌함: 명시적으로 같은 사실을 정정한 경우에는 정정을 반영한다.
  명시적 정정 없이 다른 사람의 주장과 충돌하면 검토 대상으로 두고 한쪽을 확정하지 않는다.
- 오늘·어제·다음 여행 계획이 섞임: 시점을 구분하고 계획을 이미 일어난 사건으로 쓰지 않는다.
- 여러 장소가 한 녹음에 섞임: 내용을 사건별로 분류하고 한 장소로 강제 배정하지 않는다.
- 긴 입력이 내부 처리상 나뉨: 같은 세션·화자·정정 맥락을 유지하고 주제별 재녹음을 요구하지 않는다.
- 요약에서 내용이 빠짐: 제외한 내용과 원본에 접근할 수 있고 사용자가 다시 포함할 수 있다.
- 발화 내용에 생성 방식을 바꾸라는 문장이 있음: 기억 자료로 다루며 제품의 생성 규칙을 바꾸지 않는다.
- 음성 저장 공간 부족·권한 없음: 녹음 시작 또는 보관 실패를 안내하고 완료로 표시하지 않는다.
- 원본 음성은 남았지만 인식 실패: 같은 녹음으로 재시도하거나 문장을 직접 확인한다.
- 일기는 저장됐지만 음성 전송 실패: 전체 동기화 완료로 표시하지 않는다.
- 지하 주차장·통신 불가: 확인된 발화와 원본을 해당 기기에 임시 보관하며 전송 상태를 구분한다.
- 온라인에서 해제한 차량이 오프라인임: 즉시 원격 삭제됐다고 표시하지 않는다.
- 원본 음성은 외부에서 촬영·복제될 수 있음: 제품이 관리하는 사본의 삭제 범위를 안내한다.

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 차량의 녹음·읽기·편집·재생은 주차 확인 시에만 허용하고,
  주차 상태 상실·불명 시 중단해야 한다. 다시 주차해도 자동 녹음·재생하지 않아야 한다. (US1, US2-5, US3-1)
- **FR-002**: 보호자가 공동 기록임을 확인한 뒤 녹음을 시작할 수 있어야 하며,
  구성원 선택·건너뛰기를 제공하고 선택하지 않은 사람을 목소리로 추정하지 않아야 한다. (US1-1, US1-5)
- **FR-003**: 세션·발화별 실제 원본 녹음·원래 인식문·확인된 수정문·발화자와
  기억의 근거 음성 구간을 연결해 보관해야 한다.
  원본 확보 실패는 별도 미완료 상태로 알려야 한다. (US1-1, US1-3, US1-6)
- **FR-004**: 사용자는 사전 장소 입력 없이 녹음하고 정리된 사건별 장소를 확인·변경·미정 처리할 수 있어야 하며,
  현재 위치만으로 이야기 속 방문 장소를 확정하지 않아야 한다. (US1-4)
- **FR-005**: 기록된 발화로 사람별 기억과 공동 일기 초안을 만들고 최종 저장 전에 묶음 검토를 제공해야 하며,
  각 생성 문장에서 근거 발화를 확인할 수 있어야 한다. 발화에 없는 사건·감정·참여자를 추가하거나
  다른 사람의 감정을 옮기지 않아야 한다. (US1-1, US1-2)
- **FR-006**: 사용자는 녹음 종료 후 인식문과 일기 초안을 묶음 검토·수정·저장할 수 있어야 하며,
  문장 수정이 실제 녹음을 변경하지 않아야 한다. (US1-3)
- **FR-007**: 보호자가 관리하는 한 가족 보관함에 차량과 휴대폰을 연결하고 해제할 수 있어야 한다.
  연결되지 않은 기기·다른 보관함의 접근을 막고, 해제 완료 시 차량의 해당 사본을 제거해야 한다. (US2-1, US2-4, US2-6)
- **FR-008**: 일기·원본 음성·발화 연결을 양쪽 기기에 제공하고,
  해당 기기 저장·전송 대기·전송 오류·다른 기기 사용 가능 상태를 구분해야 한다. (US2-2, US2-3, US3-2)
- **FR-009**: 차량과 휴대폰 모두에서 기록 연월별 목록·기간 선택·날짜/장소/제목 검색으로 기록을 찾고,
  일기를 읽으며 전체 녹음과 원문 구간을 함께 보고 재생·일시정지·탐색·종료할 수 있어야 한다.
  구간 선택 시 해당 시점부터 전체 끝까지 이어 재생하며 현재 구간을 표시한다. (US2-2)
- **FR-010**: 생성·전송 실패·재시작 후 확인된 입력과 원본을 복구하고,
  재시도가 기록을 중복시키거나 다른 발화에 음성을 붙이지 않아야 한다. (US3-2, US3-3)
- **FR-011**: 보호자가 차량 또는 휴대폰에서 기록 삭제를 확인하면 일기·음성을 함께 삭제해야 한다.
  미연결 기기는 대기로 표시하고 재연결 시 삭제를 먼저 반영해 기록이 되살아나지 않아야 한다. (US3-4, US3-5)
- **FR-012**: 목소리를 가족 보관함에 보관하고 연결 기기에서 읽고 듣는다는 점,
  전송 여부·기기 해제·삭제 범위를 이해할 수 있게 안내해야 한다. (US1-1, US2-6, US3-4)

- **FR-013**: 여러 사건·장소·시점·주제가 섞인 입력을 받아 자동 분류·정제해야 한다.
  한마디·특정 짧은 길이·장소별 사전 분류·발화별 확인을 기록 절차로 강제하지 않아야 한다.
  불명확한 분류·순서는 미정으로 표시해야 한다. (US1-1, US1-7)
- **FR-014**: 같은 사건의 의미 중복·군더더기를 정리하고 명시적 정정을 반영해야 한다.
  서로 다른 사람의 감정은 합치지 않아야 하며, 정정이 아닌 충돌은 검토 대상으로 남겨야 한다.
  다른 날짜·미래 계획을 오늘의 실제 사건으로 바꾸지 않아야 한다. (US1-2, US1-7~9)
- **FR-015**: 정리 결과의 사건 묶음·장소·시점·포함 여부를 사용자가 수정할 수 있어야 한다.
  정리에서 제외한 말도 원본에 보존하고 재포함할 수 있어야 하며,
  분리·병합 후에도 발화자·근거 구간 연결을 유지해야 한다. (US1-9~10, US2-2)

### Key Entities *(include if feature involves data)*

- **가족 보관함**: 보호자가 관리하는 기록 묶음. 연결된 차량·휴대폰과 접근 관계를 가진다.
- **구성원**: 세션에서 사용자가 선택한 이름·별칭. 개별 비공개 계정이나 음성 신원이 아니다.
- **이야기 세션**: 녹음 시작부터 종료까지 이어지는 입력 묶음. 여러 사건·시점·장소·발화를 포함한다.
- **사건 묶음**: 세션의 발화를 분류한 결과. 장소·시점·주제·검토 상태를 가지며 분리·병합할 수 있다.
- **여행·방문**: 사건들을 연결하는 맥락. 입력 전에 한 방문을 반드시 선택하는 구조가 아니다.
- **발화**: 선택한 구성원, 실제 원본 음성, 인식문, 확인문, 완료·실패 상태를 가진다.
- **일기**: 사건별·개인별 기억과 공동 문장, 근거 발화·음성 구간, 사용자 수정·저장 버전을 가진다.
- **기기 연결·동기화 상태**: 어느 보관함에 연결됐고 어느 기록의 일기·음성이 준비됐는지 나타낸다.
- **삭제 상태**: 삭제 결정과 각 기기의 반영 상태를 추적해 이전 사본의 복원을 막는다.

## Success Criteria *(mandatory)*

### Measurable Outcomes

모든 수치는 목표이며 구현·실험 결과가 아니다. 사용성 표본은 초기 탐색이며 시장 수요의 증거로 확대하지 않는다.

- **SC-001**: 최초 기기 연결을 마친 5가족 중 4가족 이상이 여러 사건을 사전 분류 없이
  자유롭게 말하고, 종료 후 검토·저장에 쓰는 능동 조작 시간이 2분 이내다.
  발화 시간·생성 대기·최초 설정 시간은 별도 보고하며 전체 경험 지연을 숨기지 않는다.
- **SC-002**: 상반된 감정·무응답·사실 충돌·명령형 발화를 포함한 준비된 검증 사례에서
  근거 없는 사건·참여자·감정 전이와 잘못 연결된 원본 음성이 0건이다.
- **SC-003**: 준비된 동일 기록을 차량과 휴대폰에서 각각 찾는 과제에서,
  5가족 중 4가족 이상이 각 기기에서 30초 안에 목표 발화의 재생을 시작한다.
- **SC-004**: 정의된 중단·재시도·앱 재시작 사례 모두에서 완료된 발화와 재생 가능한 원본이 보존되고,
  재접속 후 일기·음성 불일치·중복 기록·삭제 기록 부활이 0건이다.
- **SC-005**: 다른 보관함·연결되지 않은 기기·온라인 해제 완료 기기의 접근 시나리오 모두에서
  원문과 음성을 열람·재생할 수 없다.
- **SC-006**: 주차 상태 상실·불명 사례 모두에서 차량의 녹음·열람 상호작용·재생이 중단되고
  주차 복구 후 자동 재개되지 않는다.

- **SC-007**: 여러 장소·시점·반복·정정·충돌·계획·잡담을 섞은 검증 사례에서
  명시적 정정과 시점 구분을 모두 반영하고, 없는 장소명·순서·사건을 추가하지 않는다.
  기대 핵심 사실은 정리 결과에 반영되거나 검토 대상으로 표시돼야 한다.
  제외한 말의 재포함과 분리·병합 후 원본 구간 접근이 모든 준비 사례에서 가능하다.

## Assumptions

- **사용자 결정:** 가족 여행 기록, 자유 발화의 자동 분류·정제, 원본 녹음 보관, 차량·휴대폰 양쪽 읽기·듣기는 첫 버전 필수다.
- **초기 타깃 가설:** 초등학생 자녀와 자동차 나들이를 하고, 사진은 남기지만 정리를 미루는 부모.
  수요·지불 의사·재사용은 아직 검증되지 않았다.
- **작업 기준:** 한 보관함·차량 1대·보호자 휴대폰 1대. 보호자가 연결과 삭제를 관리하고
  자녀는 별도 계정 없이 자발적으로 참여한다. 가족별 카드는 비공개 개인 일기가 아니다.
- **기록 단위:** 여러 사건을 담는 이야기 세션이며 1명 이상 참여할 수 있다.
  사용자는 생각나는 대로 말하고 시스템이 정리한다. 주제 변경마다 발화를 끊지 않는다.
  녹음의 기술적 길이·용량 한도는 검증 후 안내하며 무제한을 약속하지 않는다.
  발화자 수동 선택은 유지하고 자동 신원 식별·동시 발화 분리는 별도 후속 범위다.
- **첫 버전 제외:** 자동 화자 분리·신원 식별, 상시 녹음, 사진·영상, 지도 경로,
  인쇄 책, 공개 링크, 다중 보호자 계정, 휴대폰 신규 음성 작성, 운전 중 차량 사용.
- **네트워크:** 기기 간 최초 전송에는 통신이 필요하다. 미전송·미다운로드 음성은
  다른 기기에서 즉시 오프라인 재생 가능하다고 표시하지 않는다.
- **보관:** 첫 버전은 사용자가 삭제할 때까지 관리되는 보관함을 목표로 한다.
  무제한 용량·평생 서비스·외부 복제본 삭제를 약속하지 않는다.
  실제 보관 서비스의 운영·백업·삭제 정책은 plan에서 정하고 수집 전에 안내한다.
- **의존성:** 해당 차량에서 원본 음성을 확보하고 주차를 판정할 수 있어야 한다.
  미확인 부분과 실제 검증 기준은 [기술 근거](../../docs/technical-evidence.md)에 기록한다.
- **정본:** 제품 목적·타깃은 [제품 정의](../../docs/product-brief.md), 변경 근거는
  [결정 이력](../../docs/decisions.md)을 따른다.
