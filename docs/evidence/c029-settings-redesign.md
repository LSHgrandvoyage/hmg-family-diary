# C029 차량 설정 재설계·검색 명칭·모바일 수동 테마

2026-11-12. 사용자 제공 Downloads/차량앱 설정화면.png를 시각 기준으로 구현했다. `frontend-design`, `ui-ux-pro-max`의 대비·터치 영역·포커스 기준을 적용하고 기존 제품 색상/폰트를 사용했다.

## 구성 결정

설정 첫 화면은 112px 왼쪽 탐색과 두 열 카드, 넓은 간격, 하단 버전 표시를 따른다. 1280×720 기준의 그림을 차량 WebView 크기에 맞춰 배율 적용하고 두 테마를 지원한다. PNG에 있는 기능을 그대로 작동하는 것처럼 복제하지 않고 현재 제품에서 필요한 다음 네 가지를 연결했다.

| 카드 | 제공 기능 | 포함 이유 |
|---|---|---|
| 휴대폰 연결 | 연결 여부·마지막 동기화, 코드 연결, 연결 별칭, 지금 동기화 | 자동 동기화의 연결 상태와 오류 복구 확인 |
| 우리 차 | 현재 프로필, 조회 가능한 제조사/모델/연식 제안, 별명·번호 등의 수정/저장 | 어떤 차에서 만든 기억인지 보존 |
| 녹음 위치 | 위치 권한 상태·기존 권한 안내/요청 | 녹음 시작 시점 위치 수집에 대한 사용자 선택 |
| 화면 모드 | 차량 자동/라이트/다크와 현재 적용 설명 | 차량의 주야간 신호와 수동 선택 |

입력은 별도 패널로 분리한다. 연결 해제는 기존 휴대폰 차량 관리에서 한다. 마지막 동기화 시각이 없는데 `방금 전`이라고 표시하지 않는다. 차량 조회는 사용자가 수정 중인 값과 기존 값을 덮어쓰지 않는다. 저장 실패 시 입력을 유지한다.

사용자 설정에서 샘플 위치·모의 P 해제·목업 안내·현재 연결된 개발 기능 목록을 노출하지 않는다. 플랫폼 시험용 초기 gate/별도 주행 시험 제어는 기존 검증 경로에 남는다. 자동 녹음, 주행 안전 모드 해제, 미구현 음성 안내·보관함 숨김 토글은 추가하지 않았다. 설정 첫 화면의 네 기능은 현재 구현을 기준으로 정리한 제안이며 후속 요구에 따라 조정할 수 있다.

모바일은 자동 버튼뿐 아니라 OS 자동 추종도 제거했다. 미설정/기존 auto는 라이트로 이행하고, 이후 태양/달 수동 선택을 저장한다. 차량 auto는 유지한다. 검색 버튼·패널·접근성 이름은 `검색`으로 통일하며 차량 필터 기능은 같은 패널에 남겼다.

## 구현·데이터

`settings.js`의 faithful 설정 화면과 주차 검토 권한을 확인하는 native bridge를 연결했다. 차량 저장은 기존 prefs만 바꾸고 과거 MemoryContext를 수정하지 않는다. 코드/별칭은 기존 CloudSync를 사용한다. 토큰을 WebView 응답에 넣지 않는다. 연결/수동 동기화 요청은 긴 네트워크 작업을 기다리는 동안 버튼을 비활성화하고 오류를 표시한다. 차량 정보 입력은 60자, 별칭은 1~40자, 코드는8자리 검증을 거친다. 서버 스키마/API 변경은 없다.

설정은 기존의 네이티브 긴 폼 대신 carsettings route로 표시한다. 녹음/일기 탭과 돌아가기를 연결하고, 표시 완료 전 테스트에서 숨겨진 링크를 클릭하지 않도록 계측 준비 조건을 강화했다. 숨겨진 이전 설정 위젯은 기존 내부 검증 코드와의 호환을 위해 남아 있지만 사용자 설정 진입 경로에서는 표시하지 않는다.

## 최종 적용

최종 APK에서 NavigationAppearanceDeviceTest와 PlaylistDeviceTest 2개 통과(16.339초). 새 설정/주행 제한·파형과 기존 내비게이션 중 TTS/종료 흐름까지 회귀했다. 최신 이미지로 Compose를 갱신했고 DB/web/mailpit healthy를 확인했다. 실제 HTTPS 테스트 계정 로그인 후 모바일 수동 테마·검색 명칭·X 패널·SSE 수신·인증 원본 SHA 검증도 통과했다. 기존 계정·연결·음성/사진/DB 볼륨은 유지했다.

사용자가 켜 둔 emulator-5580에 최신 앱을 설치하고 일반 앱 화면을 다시 열었다. 에뮬레이터를 종료하거나 호스트 마이크를 변경하지 않았다. 빌드는 no-daemon/in-process로 수행했다. 로컬 검토용 패키지도 갱신했고 외부 게시/전송은 하지 않았다.
