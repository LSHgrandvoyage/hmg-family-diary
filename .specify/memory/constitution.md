# HMG Family Diary Constitution

## Core Principles

### I. 사용자 문제에서 시작하는 명세

기능은 제품 정의의 타깃·문제·사용 상황과 연결되어야 한다. 구현 전에 기능 명세에
사용자 시나리오, 검증 가능한 요구사항, 성공 기준을 작성한다. 가정과 사용자 결정,
조사 근거, 실행으로 확인한 사실을 구분한다. 인기·독창성·수요를 근거 없이 주장하지 않는다.

### II. 말한 사람의 기억과 목소리 보존

일기 초안은 기록된 발화와 사용자가 정정한 내용에 근거하며 최종 저장 전 묶음 검토를 제공한다.
서로 다른 감정을 가족 전체의 감정으로
일반화하거나 참여자·사건·감정을 만들어 넣지 않는다. 발화자 선택·원본 음성·인식문·
확인문·생성 문장의 연결을 유지한다. 음성은 해당 입력의 실제 녹음이어야 하며,
나중에 인식문을 고쳐도 원본 녹음의 내용은 바꾸지 않는다.

### III. 주행 맥락별 기능과 명시적인 기록

플랫폼이 해당 주행 상태에서 허용하는 범위 안에서 사용자 시작 녹음·원본 청취를 제공한다.
주행 중에는 최소한의 음성 기능 조작만 제공하며 사진·전체 일기 본문 탐색·문장 수정·검토를 숨기고 차단한다.
사용자의2026-11-14 명시적 변경에 따라 에뮬레이터 TTS 청취에는 실제 낭독 중인 문장과 앞뒤 각2문장만 자동으로 표시한다. 전체 본문 전달·수동 스크롤·문장 선택 탐색은 허용하지 않으며 실차/마켓 허용을 입증하지 않는다.
사용자의2026-11-13 명시적 변경에 따라 에뮬레이터 주행 녹음 중에는 현재 인식문의 최근2줄만 표시한다.
전체 전사 탐색·스크롤·편집은 주차 후로 제한한다. 사용자 요청에 따라 에뮬레이터 청취 화면에서는 제목·날짜만 포함한 일기 목록을 탐색할 수 있다. 이러한 표시는 실차/마켓 허용을 입증하지 않는다.
녹음 종료 후 원본과 인식문은 보관하고 검토는 주차가 확인된 뒤 제공한다.
속도0이나 신호 대기를 주차로 간주하지 않는다. 주행 상태/플랫폼 허용이 불명하거나
오디오 포커스가 배타적으로 상실되거나 공동 녹음 동의가 상실되면 미디어를 중단하고 확인된 기록을 보존한다.
화면 이탈 자체는 사용자가 시작한 foreground service 녹음의 중단 사유가 아니다.
상시 녹음·자동 재개와 휴대폰을 통한 차량 제한 우회를 하지 않는다.
에뮬레이터 모의 주행 허용은 실차·마켓 허용의 증거가 아니며 실제 제한을 우회하는 DO 선언으로 대신하지 않는다.

### IV. 가족 기록의 접근·보관·삭제 일관성

첫 버전은 보호자가 관리하는 하나의 가족 보관함에 차량과 휴대폰을 연결한다.
녹음과 텍스트가 공동 보관된다는 사실을 기록 전에 알리고 참여를 건너뛸 수 있게 한다.
연결되지 않은 기기와 다른 보관함에서 기록을 볼 수 없도록 한다.
동기화·삭제 상태를 숨기지 않고 음성·텍스트·기기 사본의 삭제를 함께 다룬다.
실제 가족 음성, 정확한 위치, 계정 비밀정보를 저장소·분석 로그·공개 시연에 넣지 않는다.

### V. 실행 증거와 작은 완결 흐름

SDK 문서, 모의 입력, 에뮬레이터 실행, 실차 검증을 별도 증거로 기록한다.
필수 검증은 원본 음성 확보, 발화자·기록 연결, 주행 모드 분리·제한/포커스 상실 중단, 생성 충실도,
기기 간 동기화·접근 제어·삭제·오류 복구다. 테스트는 실제 동작을 검증하며
문서 변경만으로 앱 테스트 통과를 주장하지 않는다. 실패한 검증을 기능 완료로 처리하지 않는다.

### VI. 자유로운 입력과 근거 있는 정리

사용자에게 한마디·한 사건·한 장소 단위의 발화나 사전 분류를 요구하지 않는다.
여러 사건·장소·시점과 정정이 섞인 세션을 LLM이 분류·정제하고 사용자가 결과를 검토한다.
최종 검토는 묶음으로 할 수 있으며 발화마다 확인을 강제하지 않는다.
명시적인 정정과 불명확한 충돌을 구분하고, 근거 없는 시간 순서·장소·발화자를 만들어 넣지 않는다.
정리 결과와 원본 구간을 연결하며 생략된 잡담도 원본에서 보존한다.

## Product Constraints

초기 제품은 초등학생 자녀와 자동차 나들이를 하는 가족을 대상으로 한다.
부모가 진행하고 가족이 자발적으로 발화하며, 차량에서 기록한 일기와 원본 음성을
차량·휴대폰 양쪽에서 다시 읽고 듣는 흐름을 첫 버전에 포함한다.
초기 표면은 한 가족 보관함·차량 한 대·보호자 휴대폰 한 대이며, 계정별 비밀 일기,
자동 화자 식별, 사진 자동 수집, 영상, 인쇄 상품은 초기 범위에 포함하지 않는다.
사용자가 선택한 사진 첨부와 녹음 위치 기반 과거 기록 회상을 포함한다. 사진에도 가족 보관함 접근·보관·삭제 원칙을 적용한다.
기록 당시 차량 정보와 녹음 시작 시점의 위치를 보존한다. 활성 차량 한 대의 연결 제약은 과거 차량의 기억을 삭제하거나 현재 차량 정보로 덮어쓰는 근거가 아니다.
화면·플랫폼·사업 범위 변경은 관련 제품 정의와 명세를 먼저 갱신한다.

## Development Workflow

제품 정의 → constitution → specify → 필요한 clarify → plan → tasks → analyze → implement
순서로 진행하고, 각 단계의 근거와 산출물을 저장소에 남긴다.
제품 정의·기능 요구사항은 docs/product-brief.md와 specs/의 명세가 정본이다.
기술 선택과 SDK 미확인 사항은 research/plan에 분리한다. 구현 계획·작업·검증은 요구사항 ID에 연결한다.
현재는 에뮬레이터/로컬 서버 프로토타입을 구현했고 기능 정본은 `specs/README.md`에서 선택한다.
새 기능은 소유 spec의 수용 조건부터 갱신하고 plan/계약·tasks·정합성 검토 후 구현한다.
2026-11-13 기존 단일 명세 분리(C040)는 사용자가 허용한 사후 정리 예외다. 과거 개발 순서를 소급해 바꾸지 않으며 이후 구현의 예외로 사용하지 않는다.

## Governance

사용자의 명시적 방향 수정이 기존 가정보다 우선한다. 헌장과 변경되는 명세를 함께 수정하고,
영향받는 작업·검증 항목을 기록한다. 원칙의 호환되지 않는 변경은 major, 원칙 추가는 minor,
의미를 유지한 설명 수정은 patch 버전을 올린다. 변경 검토에서 원칙 준수와 근거를 확인한다.
새 승인 절차를 임의로 추가하지 않으며, 이미 요청된 범위의 명세·계획 작업은 계속 진행한다.
